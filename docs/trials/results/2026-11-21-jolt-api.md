# API trial: helix-jolt's draft (2026-11-21)

Whether agents who know JoltPhysics.js can write a program against helix-jolt's draft API from its types and doc comments alone:
Jolt Physics with JoltPhysics.js's API in Haxe, not built yet. Nine fresh Sonnet agents in three rounds of three, each a `claude -p`
in a directory of its own outside any repository, in the blind trials' sandbox (`run_entrant.py --trial`), compiling for JavaScript
against the draft's sources (`-cp docs/api`) and helix-math at `866fd91`. Each was given the draft brief made for Jolt, the draft's
sources and README, and a task naming no call: layers, a floor and a tilted ramp, a stack of boxes and bouncing balls, a static mesh
built from its own triangles, a kinematic platform moved back and forth, a trigger zone printing what enters and leaves, a door hinged
to the world turned by a limited motor, an impulse at 2 seconds, every moving body's pose read into one buffer each step without
allocating, a ray cast down each second printing the height, normal and body hit, and at the end the bodies awake, each ball and the
door's angle. The draft changed between rounds as below. The inputs were made outside the repository beside the runs.

## What it found

| finding | what changed |
|---|---|
| No body standing for the world, so each hinged the door to a static body of its own (3 of 3, round 1) | `JoltInterface.sGetFixedToWorldBody`, as JoltPhysics.js has it, and `BodyInterface.CreateConstraint` says an invalid id fixes the other body to the world, as Jolt's does. Round 2: 3 of 3 used it |
| No `Body` from a `BodyID`, so the hit's normal went through `GetTransformedShape` (3 of 3, round 1) | `PhysicsSystem.GetBodyLockInterfaceNoLock().TryGetBody`, as JoltPhysics.js has it, and `RayCastResult.mSubShapeID2` shows the call. Round 2: 3 of 3 used it |
| `CreateConstraint` returned a `TwoBodyConstraint` to cast to `HingeConstraint` (2 of 3, round 1) | Each settings class names its constraint (`HingeConstraintSettings extends TwoBodyConstraintSettings<HingeConstraint>`), and `CreateConstraint` returns it. Round 2: no cast |
| Whether `Release` is needed after `Jolt.destroy` (2 of 3, round 1) | `Jolt.destroy`, `Shape` and `Constraint` say destroy frees everything, held or not, and a call after is skipped |
| What a static sensor detects (3 of 3, round 1) | `mIsSensor` says: awake dynamic and kinematic bodies in layers its layer collides with, a body falling asleep inside reported as leaving, a kinematic sensor seeing sleeping bodies |
| When to call `MoveKinematic`, and where the hinge angle starts (2 of 3, round 1) | `MoveKinematic` is called before `Step`, the body arriving at the step's end. The hinge's and slider's 0 is the pose when made. Every constraint setting gives its default |
| A constant (`EActivation_Activate`) not found where no type is expected: a default argument, an untyped `var` (1 of 3, round 2). A Haxe enum's constructors and module-level fields aren't imported by `import helix.jolt.*` either | Every constant is on `Jolt`, as JoltPhysics.js has them on its module: `Jolt.EMotionType_Dynamic`, or bare after `import helix.jolt.Jolt.*;`, which the README and brief name. Round 3: no compile error |
| The sensor "either" body in a contact event (1 of 3, round 2) | The sensor is `mBodyID1`, and of two other bodies the lower index |
| Two doc examples declared a variable from itself, which doesn't compile (1 of 3, round 3) | Fixed. `BodyID` declares `==` and `!=` (3 of 3 asked, round 3), and `ConvexShape` says a 1 meter box weighs 1000 kg |
| `Sys.println` in JavaScript (3 of 9) | nothing: Haxe's, not the library's |
| `AddForce`'s optional point before a required argument (2 of 9) | nothing: Jolt's own two overloads, both of which compile |
