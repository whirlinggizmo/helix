Do the task in `{DIR}/task.md` in Haxe, using **raylib 5.5's API**.

- **How raylib looks here.** This is raylib 5.5 in Haxe. Each raylib header is a class in package `helix.raylib`: `raylib.h` is `helix.raylib.Raylib`, and `import helix.raylib.Raylib.*;` brings its functions, constants and colors in unqualified, as raylib names them. `raymath.h` is `Raymath`, `rlgl.h` is `Rlgl`, `raygui.h` is `Raygui`, and the examples' `rlights.h` is `Rlights`. raylib's structs are classes of the same names and fields in `helix.raylib`. Write it as you would write a raylib program.
- **Extras.** helix-raylib adds calls raylib hasn't, in `helix.raylib.extras`, each module imported apart (`import helix.raylib.extras.Models.*;`). Their doc comments are in `{DIR}/docs/extras/`, a page for each, listed in its README.md, and a small program using each in `{DIR}/docs/extras/examples/`: read the ones you need, and use what helps.
- **Docs:** raylib 5.5's own headers are in `{DIR}/docs/include/`, raygui's and rlights' in `{DIR}/docs/headers/`, and its C examples in `{DIR}/docs/examples/`. Read them, and `{DIR}/docs/extras/`, as you need. Read nothing else about the library: no library sources, no other documentation, no web. Where it differs from raylib in C, the compiler tells you.
- **Building:** in `{DIR}`, `haxe build.hxml` builds the program natively as `native/Main`. You may add to `build.hxml`. Build as often as you like.
- **Running:** `./native/Main [arguments]` from `{DIR}` runs it, passing it the arguments. It runs on a display of its own, never on the desktop, with no sound. The program must exit on its own, as your shell waits for it, so give it a way to stop (an argument naming the frames to run, say). To see it, save screenshots with raylib's call for it and look at them.
- **Writing:** write to `{DIR}` only: the program's `.hx` files (`Main.hx` and what it imports), its shaders, and `build.hxml`, then `NOTES.md` as `task.md` asks.
