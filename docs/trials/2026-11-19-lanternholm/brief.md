Build the program in `{DIR}/spec.md` in Haxe, using **raylib 5.5's API**. It makes everything in code: there are no asset files.

- **How raylib looks here.** This is raylib 5.5 in Haxe. Each raylib header is a class in package `helix.raylib`: `raylib.h` is `helix.raylib.Raylib`, and `import helix.raylib.Raylib.*;` brings its functions, constants and colors in unqualified, as raylib names them. `raymath.h` is `Raymath`, `rlgl.h` is `Rlgl` and `raygui.h` is `Raygui`. The lights of the examples' `rlights.h` (`CreateLight`) are in the Lighting extra (`import helix.raylib.extras.Lighting.*;`). raylib's structs are classes of the same names and fields in `helix.raylib`. Write it as you would write a raylib program.
- **Extras.** helix-raylib adds calls raylib hasn't, in `helix.raylib.extras`, each module imported apart (`import helix.raylib.extras.Models.*;`). Their doc comments are in `{DIR}/docs/extras/`, a page for each, listed in its README.md, and a small program using each in `{DIR}/docs/extras/examples/`: read the ones you need, and use what helps.
- **Docs:** raylib 5.5's own headers are in `{DIR}/docs/include/` and its C examples in `{DIR}/docs/examples/`. Read them, and `{DIR}/docs/extras/`, as you need. Read nothing else about the library: no library sources, no other documentation, no web. Where it differs from raylib in C, the compiler tells you.
- **Reference:** `{DIR}/reference/` holds screenshots of what the spec describes, 1280 x 720: at dawn, noon, dusk and night, and close up at noon. Compare yours with them.
- **Building:** in `{DIR}`, `haxe build.hxml` builds the program natively as `native/Main`. You may add to `build.hxml`. Build as often as you like.
- **Running:** `./native/Main [arguments]` from `{DIR}` runs it, passing it the arguments (as `--hour=0.5 --frames=120`). It runs on a display of its own, never on the desktop, with no sound. The program must exit on its own, as your shell waits for it, so give it a way to stop (the spec's `--frames`). To see it, save screenshots with raylib's call for it and look at them. Run it in the foreground: a program left running in the background keeps your session from ending.
- **Writing:** write to `{DIR}` only: the program's `.hx` files (`Main.hx` and what it imports), its shaders, and `build.hxml`, then `NOTES.md` with each compile error you hit, in order, and what you changed for it; each place raylib's API and the extras had no call for what the spec asks and what you did instead; each place you were left guessing and what you guessed, the extras' calls among them; and anything you expect not to work.
- **Budget:** stop at 4 hours or when the spec is met, whichever comes first, and reply with one line saying which.
