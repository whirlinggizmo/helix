Do the task in `{DIR}/task.md` in Haxe, using **raylib 5.5's API**.

- **How raylib looks here.** This is raylib 5.5 in Haxe. Each raylib header is a class in package `helix.raylib`: `raylib.h` is `helix.raylib.Raylib`, and `import helix.raylib.Raylib.*;` brings its functions, constants and colors in unqualified, as raylib names them. `raymath.h` is `Raymath`, `rlgl.h` is `Rlgl`, and the examples' `rlights.h` is `Rlights`. raylib's structs are classes of the same names and fields in `helix.raylib` (`import helix.raylib.*;`). Shaders are raylib's GLSL, compiled as the program builds by a line in `build.hxml` for each (`--macro helix.raylib.Raylib.CompileShaderFile("shaders/shadowmap.vs", "shaders/shadowmap.fs", "shaders/shadowmap.shader")`) and loaded with `LoadCompiledShaderAsync`. Write it as you would write a raylib program.
- **Shadow maps.** raylib's example makes its shadow map with rlgl calls helix-raylib doesn't have. helix-raylib gives the example's own two functions in their place, in `helix.raylib.extras.Shadowmaps` (`import helix.raylib.extras.Shadowmaps.*;`). Their doc comments are in `{DIR}/docs/api/helix/raylib/extras/Shadowmaps.hx`: learn them from it. They aren't built yet, so the program is compiled, not run.
- **Docs:** raylib 5.5's own headers are in `{DIR}/docs/include/` and its C examples in `{DIR}/docs/examples/`. Read them as you need. Read nothing else about the library: no library sources, no other documentation, no web.
- **Assets:** the example's files are in `{DIR}/docs/examples/shaders/resources/`. Copy its shaders into `{DIR}/shaders/` and change them as helix-raylib needs.
- **Building:** in `{DIR}`, `haxe build.hxml` compiles it to JavaScript. You may add the shaders' lines to `build.hxml`.
