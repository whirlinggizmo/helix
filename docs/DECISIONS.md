# Decisions

Decisions are chronological. HeliX began as experiment 05 of a framework architecture study (whirlinggizmo's wgf-architecture-experiments), which compared it with libwgf; the entries before it moved into this repository were made there, so they name that study, its parity comparison and its results, which stayed with the study. Entries 21 onward supersede the earlier SDL2 and minimal-loader choices; preserved SDL2 measurements are historical, not the current implementation.

1. Separate experiment05; no edits to prior experiments, shared documents or libwgf. Read the comparison plan and new brief/start prompt before implementation. Use only the prior experiment's pinned third-party Sokol headers as a read-only build dependency.
2. Shared Haxe owns game simulation and all rendering decisions. Compile-time classpaths supply `Platform`/`GraphicsBackend` with matching interfaces. There are no target conditionals in the shared sources. Native bindings, C resource calls and browser extern calls are confined to adapters.
3. Use a small subset of real Sokol operations, one fixed 32 B position/UV/color vertex record and one textured-color shader. One prepared expanded triangle batch is appropriate for this ordinary Asteroids slice; avoid introducing scene policy into the HAL or promising a complete multi-backend GPU framework.
4. Generate both shaders from one authored annotated GLSL file using pinned sokol-shdc. Native initial backend is GLCORE, browser WebGL2. Metal/Vulkan/WebGPU requires new builds and execution; shader generation alone is not portability proof.
5. Use original generated bitmap glyphs and colored geometry with one atlas. No art/files/services are taken from libwgf. Title/game-over screens are simple shared-renderer text, not a substitute claim for Clay or a reusable layout system.
6. Fixed-point positions/velocities and an integer heading table avoid repeating the prior simulation-trigonometry issue. RNG and replay are shared Haxe. Geometry additionally hashes actual float32 bytes. Live play uses fixed 60 Hz accumulation with bounded catch-up; benchmark replay uses exactly one step per delivered frame and reports cadence separately.
7. Common Haxe creates reusable float32 sound clips. Browser Web Audio unlocks after user input; native SDL2's audio device mixes copied clips, with16 voice slots. Native audio cannot be called an audible-output pass from a dummy device; browser/network audio streaming is not exercised. Missing device is reported and does not stop graphics.
8. Three CPU trials per target, sequential and uninstrumented; frozen audit/image checks separate. Record actual program totals with full Haxe DCE/analyzer and Terser, same per-file gzip9/Brotli11, page included. Include diagnostics instead of presenting an unverified hypothetical production minimum.
9. Local startup clocks exclude browser download/script evaluation before Haxe entry; native clock includes window acquisition. Do not infer matched cold startup or a native speed advantage from them. Dynamic native dependencies and their exclusions remain explicit.
10. Native input tooling holds a key until its state transition is observed rather than relying on a sub-frame pulse, finds its own window by PID, and forcibly cleans up when Sokol ignores SIGTERM. Diagnostic live writes are disabled in CPU cohorts. Authorized screen overrides restore exact prior state even on a failed check.
11. Context loss/device recovery, shader/resource breadth, further platforms, gamepads/touch, asset services, sustained GC/memory and feature-matched libwgf comparison remain follow-ups. The interface's first proof is one shared renderer serving two real adapters; size differences against another game are contextual, not a measured same-feature saving.
12. Parse sokol-shdc's structured `bare_yaml` reflection with pinned PyYAML6.0.1; never scrape generated shader/C text or select stale shader files by glob. Keep CPU packing roles/order in one small JSON schema because shader inputs do not specify buffer byte offsets. Generate Haxe inline layout constants and native C layout/binding metadata, validate cross-dialect agreement, and compile native static assertions against shdc's own constants. This is offline shader reflection, not Haxe runtime reflection. Reject unsupported schema/resource growth and test real compiler fixtures with relocated/renamed bindings before upgrading the pinned generator.
13. Move reusable contracts/utilities into `framework/hybrid`; retain the game in `src`. `IHost` composes independent `IInput`, `IAudio`, `IAssets` and `IGraphics` services; experiment hooks move to `IDiagnostics`. An independent consumer type-checks contracts and runs input/autopilot under interpreter/JS without game/adapter/generated-shader classpaths. No package manifest or publication is implied.
14. Normalize physical key names, primary framebuffer-pointer coordinates and mapped controller buttons/axes in adapters; action/dead-zone/menu policy stays shared. Preserve keyboard/pointer edges until a fixed tick consumes them. Clear input on focus loss, pause live simulation and stop thrust. Browser Gamepad API fixtures and an actual SDL virtual controller verify mappings; physical controllers remain untested. SDL supplies controller/audio services only, leaving Sokol as sole native window owner.
15. Load eight original PCM16 WAV files through a minimal asynchronous asset interface, decode/validate them in shared Haxe, and create copied PCM clips through `IAudio`. Browser uses fetch/Web Audio; native uses file-reading workers, host-thread completions and SDL mixing. This supersedes runtime synthesis in decision7. Native loader concurrency is adequate for this bounded slice, not a scalable asset manager. No streaming or audible-native-output claim.
16. Approximate representative reference gameplay/presentation with 960×720 layout, title rocks, clickable/focusable buttons, life icons/session best/extra lives, six-bullet cap, wave/respawn delays, varied rocks, particles and thrust looping. Keep independently authored fixed-point simulation, bitmap font, geometry and sound assets. This supersedes the simpler presentation in decision5 and some deferred items in decision11; it is still not a full equivalent ECS/prefab/UI port.
17. Record an intermediate service extraction with original game rules before gameplay growth. Its size delta includes exercised input/clip-voice capability, not just interface declarations. Final delivery separates code+HTML, eight sound files and optional autopilot/manifest. WAV encoding dominates current delivery; compressed audio is the next size gate. Shared framework/game continue to contain zero target conditionals.
18. Autopilot parses bounded versioned JSON commands into normal input, with explicit application probe callbacks. It uses ordinary Reflect only to validate JSON fields; no source scraping, private game-field reflection or game-state mutation. Full rendered browser/native playthrough matches 4584 ticks/outcomes/state/pixels. Fast mode is correctness tooling; the separate real-time replay remains the CPU cohort.
19. Keep HXML as compiler configuration and Python as external-tool orchestration. `helix.py` is the single build/test/check/autopilot/serve/measure/sizes/report front door; `Run.hx` optionally delegates from Haxe. Tooling stays outside runtime classpaths. A future haxelib can package the Haxe API and adapters, but native glue, shader generation and platform dependencies still need consumer-facing integration. See PACKAGING.md for actual checks and remaining package work.
20. Fractional text sizes exposed nearest-filter texel ties across browser/native GPUs. Apply one shared 0.01-texel glyph UV bias; the final five snapshots and autopilot image match RGB exactly. Do not relax image checks to hide a renderer difference. All latest correctness, CPU and autopilot evidence identifies the same artifacts; authorized screen overrides restore exact prior state.
21. Use Sokol app/graphics/audio as the executed native baseline. Add the exact pinned upstream sokol_audio header with its license inside this experiment. Sokol has no gamepad API; replace the SDL2 dependency with a small Linux evdev prototype, explicitly deferring physical-device and broad mapping validation. Dummy mixer/pipe tests and real ALSA callbacks are separate evidence. This supersedes the native choices in entries 7, 14 and 15. Preserve SDL2 and pre-fetch Sokol cohorts under results/archive/pre-helix/stages without inventing an unmeasured intermediate size.
22. Keep SDL3 in consideration for a complete native adapter: graphics, window/input, gamepads and audio, as explicitly requested. Interfaces allow independent or mixed selection. Desktop performance matters more than executable size; implementation and matched modern-backend/input/audio tests must precede a recommendation between native adapters. No SDL3 implementation/performance claim exists yet.
23. Split IFetch and IStorage mechanisms from shared AssetService. Callbacks expose completion, cancellation and progress, while bounded queues/workers and cooperative host pumping remain internal. Browser Fetch/ReadableStream and IndexedDB use native browser APIs, with no Wasm; native uses haxe.Http and file workers. Limit whole-file operations to 8 MiB and two active workers/transfers per adapter. A nominal 2 ms work slice cannot preempt a slow callback/decode/disk operation; large/direct-to-storage downloads are a future gate.
24. Define assets as encoded source files, resources as reusable runtime data, and instances as individual uses. AudioClip is decoded PCM, AudioStream is a progressively decoded source, AudioPlayback is one playing/paused instance. Releasing caller ownership retains a resource until all playbacks stop/finish. No persistent AudioSource/emitter is needed for this slice. Shared Haxe owns policy/lifetimes; browser media APIs and native Sokol own delivery mechanisms.
25. Streams check usable encoded storage first, using leased browser Blob URLs or native files, then browser remote media URLs. Remote playback does not persist; ensure first when persistence is required. Stored streams are not proof of network streaming. Native canonical mono PCM16/44100 WAV progressively feeds an 8192-sample float queue per playback; remote native streaming and codecs are explicit later gates. No simultaneous play-and-store path is claimed.
26. Run the same Haxe service suite on real browser/native adapters with isolated HTTP fixtures and two persistent-storage runs. Assert one ensured-WAV download per target across ensure/clip/stored-stream use; separately verify remote browser playback leaves the cache empty. Cover concurrency, progress, status, overflow, timeout/cancel/shutdown, committed storage, independent playback, pause/resume and final resource/source cleanup. An IndexedDB Blob must store only Bytes.length, not the spare capacity of a BytesBuffer backing array; the exact RIFF-length cache regression is tested.
27. Keep prototype limits explicit: cache identity is base URL/path rather than a versioned integrity manifest; no eviction/revalidation/deduplication; storage cancellation may leave a committed write; native cancellation is logical, native socket timeout differs from browser wall-clock deadline, redirects are not normalized and HTTPS has not executed. CPU game cohorts exclude service polling and do not measure concurrent streaming/download work. Refresh all current builds/cohorts/sizes after policy integration; preserve same-compressor accounting and exact screen restoration.
28. Add asynchronous `IAudio.decodeClip` beneath shared loading/lifetime policy. Browser Vorbis/Opus use Web Audio with owned input bytes; native uses a small libsndfile 1.2.2 bridge with pinned official SDK/license and a dynamic library, leaving Sokol PCM delivery unchanged. Normalize mono/stereo Ogg clip inputs to mono 44100 Hz; cap returned clip PCM at 8 MiB and use two native decoding workers. Native stored streams decode in chunks and rewind on loop. Keep host-fed queue underruns, decoder allocations, logical cancellation and native network streaming limits explicit. This supersedes the Ogg deferrals in entries17/25 without claiming MP3, stereo output or progressive network playback.
29. Encode the same eight independently generated WAV sources offline as quality 3 Vorbis; preserve source WAVs outside deployed assets. FFmpeg is tooling, not runtime. Opus is also supported and tested with a stereo 48 kHz fixture but is not needed in the game delivery. Retain pre-Ogg measurements in results/archive/pre-helix/stages/05-services-cohort and rerun identified game/service/image/CPU cohorts with the actual new artifacts. Same gzip9/Brotli11 accounting separates code from sounds; lossy encoding is not bit-identical audio equivalence.

Record commits, clean/dirty state and exact input hashes, reject snapshots that change during extraction, and label all functions individually unverified. Do not infer full 1:1 parity or a web performance win from one atlas/shader/draw; no new physics implementation or root/shared-document edits are included.

This experiment supplies its own Sokol headers. Supersedes the layout/naming in entries 2 and 13.

38. Supersede the first HeliX layout’s root `native/` and `platforms/` directories. One fixed generated shader can serve both opaque/alpha pipelines, as in native Sokol and the inspected libwgf sprite path. Keep the original browser calls as an explicit probe baseline; cache invalidation follows frame/resource boundaries. Validate output and compare repeated trials before adopting a command representation.
43. Repeat each P1 case in forward/reverse/permuted order, with 60 warmup +90 measured frames and a drain. Preallocate samples/commands. Record actual callback-start intervals independently of filtered simulation dt. 44. **Use allocation events for rate; make hot range offsets mandatory.** hxcpp's current-heap counter is block based and can decrease during GC-disabled profiling, so it is not a valid allocation-rate counter. A separate `HXCPP_TELEMETRY`/stack-trace target captures a known 4096-byte fixture and parses telemetry v1 events. It found 16-byte Int boxing for offsets above 255, from anonymous command-field Dynamic conversions and optional offset handling. The required-offset-only diagnostic left allocation unchanged; typed command records removed the remaining conversion. `IGraphics.draw` now requires an explicit Int offset on both targets. Independent checks, allocation profiles and repeated timings were rerun after the change. Normal deliveries exclude telemetry and the GL audit interposer.

45. **Select verified browser reuse in the game launcher.** Asteroids enables cached WebGL state and a shared generated program across fixed-state pipelines. P1 retains separate baseline/cached/shared configurations. Exact pixels, lifetime checks and actual-call audits support this change; case-order variability and sequential target runs prevent a universal speedup claim. Scene order/sorting remains in Haxe. P2 clipping and texture updates are the next graphics pressure workload, with broader shader/sampler/pass support added when exercised.

46. Reset native uploaded-byte bookkeeping when a Sokol buffer slot is recreated. The independent native profiling launcher exercises destroy/recreate in the same pass, confirms slot reuse, rejects an unuploaded new generation and accepts it after upload. This lifecycle fix changes only native artifacts; browser cohort identities remain exact.

47. **Compare against libwgf with its own game source.** Run libwgf's Asteroids Haxe files, scene and sounds unchanged on HeliX through an example-local `wgf` compatibility layer, and build the reference from a pinned `git archive` into experiment-owned outputs. Gate on exact image equality and full recorded-frame agreement rather than tolerances chosen after failure. Two graphics additions were needed: per-texture linear filtering (font coverage) and a configurable clear color (letterbox bars), both below the existing contract.
48. **Pin hxcpp to the release libwgf's CI uses.** Native builds use hxcpp 4.3.2 from lib.haxe.org in an experiment-local haxelib (`build/haxelib`, selected with `HAXELIB_PATH`), so both engines build with the same toolchain as libwgf's CI and the global haxelib is untouched. Selecting a version in hxml is insufficient because Haxe invokes `haxelib run hxcpp` unversioned. `tools/pins.py` installs on a miss and stops a native build unless it resolves exactly the pinned release. Recent upstream hxcpp releases (v4.3.106 onward) break `haxe.zip.Uncompress.run` above 64 KiB output (fix proposed in HaxeFoundation/hxcpp#1422); 4.3.2 predates that change.
49. **Hosts call the app through an object.** `IHost.run(app:IApp)` replaces three callbacks. A bound method passed at start-up keeps its old code after a hot reload; a call through the object reaches the new class. `BaseApp` gives empty defaults, so an app overrides only what it uses and new callbacks can be added later without breaking apps; an app that already has a base class implements `IApp`. Chosen over an optional-field structure, which would mean dynamic field access per call on hxcpp.
50. **Generated shader source is code, not a static value.** hotreload-hx keeps every static's value across a reload, a `final` too, so `GeneratedShader` returns its source from functions. The WebGL2 adapter rebuilds a changed program after a reload, in development builds only (`#if hotreload`).
51. **Assets reload in place, through subscriptions.** A changed file is fetched once past every cache and handed to each subscriber of its path (`IAssets.subscribe(path, IReloadable)`), called through the object so new code runs after a code reload. Framework resources subscribe like any other owner: `AudioResources` swaps a clip's backend clip under the same handle and retires the old one once nothing started from it plays (libwgf's model: the old stays until the new is ready). The trigger is hotreload-hx's changed-file notice, not `@:afterHotReload`, since saving an asset rebuilds no code.
52. **Wait 3 s after waking the display before rendering evidence.** GL started while a just-woken display is still settling can filter differently on NVIDIA (a minified glyph one level apart, identical input), so `tools/display.py` waits a fixed 3 s after its wake commands; with DPMS off, xset no longer reports the monitor's state to wait on. Measured: 8/8 and 10/10 stable frame-300 captures with the wait, about half off by one without.
53. **A 2D layer named for a 3D one beside it.** `helix.render2d` holds `Batch2D`, `Camera2D`, `Texture2D`, `Font2D` and `Text2D`, generalized from Asteroids' private renderer when Blocks needed them; 3D types will take the 3D names. Drawing is immediate, in world units through the camera, and stays framework logic in Haxe over the unchanged `IGraphics`. Asteroids keeps its own renderer so its parity evidence is untouched.
54. **Touch is gestures over the existing pointer.** `PointerGestures` reads taps, drags and flicks from `IInput`'s single pointer; the browser adapter follows only the first finger. No multi-touch contract until a game needs one. Keys Z, X, C, P and Shift are appended on both targets.
55. **The edit loop regenerates shaders.** An example's dev command watches its `.glsl` source and reruns `sokol-shdc` and the generator, so shader edits reload like code. Native builds, tests and autopilot are checkpoints, not steps after each change.
56. **The C adapters' prefix is `helix_`.** `hy_`/`HY_` were left from when the experiment was called "hybrid". Renamed everywhere at once (the C sources and headers, the externs' `@:native` names, the native tests, the shader metadata generator), with no aliases: docs/CONVENTIONS.md keeps no backward compatibility. This supersedes 36's "preserve the internal `hy_*` C ABI".
57. **Frame timing is measured, as wgrender-c did.** Both hosts time frames on their own clock (`FrameClock`), not with Sokol's smoothed duration, whose sum drifts from wall time when swaps are irregular. `frame(dt)` is held between 1e-6 and 0.1 s for animation; `IHost.getFrameElapsed()` is the unheld time a `Ticker` takes, so a slow frame is caught up in ticks, up to its step limit, instead of lost.
58. **Asteroids and Blocks are examples like the rest.** Both draw through `Batch2D`/`Camera2D`/`Text2D` (Asteroids' letterbox is `Camera2D.setViewportArea`), tick with `Ticker`, start from the shared launchers, and build, develop and autopilot through `tools/example.py`. Asteroids' private renderer, shader, bitmap font and launchers are gone, with the harness built around them: vertex-byte hashes, frozen-frame image comparison, the xdotool input run, CPU and size measurements and the thrust audio check. What remains is one autopilot check for any example: the same final game on both targets. Test audio comes from `tools/fixtures.py`, not from an example.
59. **3D starts with a frame the app owns and framework shaders by kind.** `IGraphics.beginFrame(width, height, clearColor)` clears color and depth; batches set their own viewports and draw inside it; the app ends it, so offscreen passes can come later without nesting. Pipelines take a `PipelineKind` (`Sprite2D`, `Color3D`, `Lines3D`) instead of user shaders: the contract grows by what an example needs. The shader generator reads a manifest of programs (`shaders.json`) and their uniform blocks; names carry each program's prefix, since every header compiles into one C file. The WebGL2 adapter's study-era `cacheState`/`shareShader` variants are gone: one program per shader. `Batch3D` shades on the CPU, like wgrender-c's hello3d draws flat sokol_gl colors; shader lighting waits for the lights example.
60. **Simulations get their own trigonometry.** Measured: `Math`'s transcendental functions differ by an ulp between V8 and glibc for 1–18% of inputs, and a simulation turns that into a different game on each target. `helix.math.Trig` (`sin`, `cos`, `tan`, `atan2`, `asin`, `acos`) is built from arithmetic, `sqrt` and `floor` alone, each step its own statement, in double: a reduction by pi/2 in three parts, then Taylor polynomials. The test holds the interpreter, JS and hxcpp to one hash of 1.2 million results and the edge cases; native code using it compiles with `-ffp-contract=off`, since a fused multiply-add (GCC's default on arm64) rounds differently. Drawing keeps `Math`, which is faster and needn't agree. One thing the test found: hxcpp passes a local function's `Float` argument through `Dynamic`, which turns `-0.0` into the integer 0.
61. **Retained stages beside the immediate batches, made of render nodes, not a game tree.** As the earlier frameworks did, HeliX keeps both modes: `Batch2D`/`Batch3D` draw what a frame says, and a `Stage3D` (a `Stage2D` later) keeps nodes and draws them with culling, sorting and instancing. To stay out of the traps of engines whose node tree is the whole game: (1) nodes only draw (model, light, camera; sprite and text later), never timers, audio, physics, input or logic; (2) a node is a transform, children and its kind's data, and nothing is added by subclassing it; behaviors, if they come, are a list on the node, never child nodes; (3) nodes have no per-node callbacks, signals or notifications, world matrices update by dirty flags, and the stage walks arrays; a flat stage is the normal case, hierarchy only for real attachment; (4) references are objects, never string paths; (5) the simulation lives outside the tree: game state is the truth (with `helix.math.Trig` where it must replay alike) and nodes are its view, updated once a frame. Behaviors and components wait on the game model.
62. **Lit models: an instance buffer, a trimmed PBR shader.** `Stage3D` writes each model's record (its matrix's rows, its normals' matrix's rows, its tint) into a stream vertex buffer stepped once an instance, and offsets that binding to a run's first record (sokol's `vertex_buffer_offsets`, WebGL2's attribute offsets), where the earlier framework kept records in a float texture read by `texelFetch` because WebGL2 has no base instance: the same effect with no texture and no extra fetches. `lit3d.glsl` keeps that framework's glTF BRDF (Lambert, GGX/Smith, Schlick), its light falloff and Khronos PBR Neutral, trimmed to a base color texture, 4 directional or point lights and ambient light. The shader generator reads instance attributes and a uniform block a stage from `shaders.json`. Generated meshes wind each triangle from its normals, so no shape can be inside out.
63. **Normal maps: tangents generated, textures by role.** Generated meshes carry tangents, worked out from each triangle's positions and texture coordinates as the earlier frameworks did (glTF's convention: w the bitangent's sign, the map's green toward decreasing v). The instance record's spare w carries the placement's handedness. A program's textures are listed by role in `shaders.json` (`atlas`, `base`, `normal`), each with its own sampler. Texture scale and offset wait for a repeating sampler: with clamped edges they would stretch, not tile.
64. **Model files are read in Haxe, not an adapter.** glTF is data the framework interprets the same on every target, so `Gltf`, `ModelFile` and `Models` are Haxe in `helix.render3d`; the earlier framework's C loader (on cgltf) served only as a record of what to read and its defaults, as a Haxe glTF reader (heaps-gltf) did for the format's details. Only decoding the embedded images goes through an adapter, as every image does. Adapters stay platform bindings (sokol, libsndfile, stb_image, evdev) and the engine stays Haxe.
65. **`Stage2D`: render nodes drawn through a `Batch2D`.** A 2D stage keeps `Node2D`s under the rules of entry 61 (kinds made by static constructors: group, sprite, rectangle, circle, line, polygon, text; no subclassing, no callbacks, world transforms by dirty flags) and draws them depth first, in tree order, through a batch: no sorting, since 2D draws in order. The batch gained a transform (`setTransform`, a 2x3 affine applied to every vertex) so every shape and text it draws can be turned and scaled, and cameras per run (`setCamera`), so a world and a HUD share one upload, each in its camera's viewport. Nodes outside the camera's view are skipped by their transformed bounds. Outlines are in the node's own units, as everything else is, not the earlier framework's screen pixels. Concave polygons are filled by ear clipping (`Polygon2D`), worked out when their points are set. The earlier framework's 2D emitter waits for particles (milestone 4), which will serve both stages; picking waits for milestone 5 (scene and pick), and until then a node's `toLocalX`/`toLocalY` let a game test the pointer itself.
66. **Sampling belongs to the draw; compressed textures pick their file.** A texture no longer fixes its filter when it is made: `IGraphics.draw` and `drawMesh` take a `Sampling` (linear or nearest, wrap clamp, repeat or mirror along u and v) with each texture, and the adapters keep one sampler object for each value used (sokol's `sg_sampler`, WebGL2's sampler objects), linear sampling going through the mipmaps when there are any. `Texture2D` carries the sampling its draws use, read when a batch takes the texture, so one texture can be drawn smooth and then sharp; glTF samplers' filters and wraps are now read (glTF's default wrap is repeat). `createTexture` takes a `TextureFormat`, RGBA8 or a compressed one (BC7, ASTC 4x4, ETC2 RGBA8), and `canSample` says which this GPU has (sokol's pixel format query; WebGL2's extensions). KTX 1 files are read in Haxe (`Ktx`); a path `name.ktx` loads `name.bc7.ktx`, `name.astc.ktx` or `name.etc2.ktx`, the first this GPU samples that loads, else `name.png`. The files are made beforehand; HeliX has no compressor of its own yet.
67. **TrueType is read and baked in Haxe, at run time and for the built-in font.** Fonts are data the framework interprets the same on every target, as model files and KTX files are: `TrueType` reads glyf outlines (simple and composite), the Unicode character map (formats 4 and 12), metrics, and kerning (GPOS pair adjustments, formats 1 and 2, else the kern table), and `FontBaker` flattens outlines to segments within a twentieth of a pixel and stores each texel's signed distance (nonzero winding), as the built-in font's field always was. `Fonts` loads a `.ttf` into a `Font2D` (printable ASCII and Latin-1, with kerning in `Text2D`) and bakes it again when the file changes. The built-in font is baked by the same code under the Haxe interpreter at build time (1.4 s), replacing the stb_truetype C baker: its fields match stb's to within 3 of 255 (mean 0.15) with the same glyph boxes and advances. A platform rasterizer (canvas in the browser, a C library natively) was the alternative: fewer lines, but glyphs that differ between targets and engine code in C. CFF (PostScript-outline) fonts aren't read.
68. **Render targets are passes before the screen's, stored top row first.** `createRenderTarget` makes a texture (with a depth buffer of its own) that `beginTargetPass`/`endTargetPass` draw into; a frame is its target passes, then the screen's (`beginFrame` to `endFrame`). GL's framebuffers start at the bottom left, so the adapters draw a target pass flipped, as the earlier framework did: the 3D kinds' view-projection has its y row negated, Sprite2D has a clip-scale uniform the adapter sets, the viewport is mirrored, and a culling pipeline uses a twin whose front faces wind clockwise. A target then samples like any texture, and nothing above the adapter knows. Since one batch or stage can draw into a target and the screen in one frame, `updateBuffer` may now run any number of times a frame: sokol accepts a transient write only before the buffer's first bind in a frame, so the sokol adapter moves a stream buffer's later writes to extra buffers of the same size, made when first needed (WebGL2 draws as it goes and needs nothing). `Camera3D.setOrthographic` came with it, for the minimap. The example's globe showed the generated meshes' round sides had u running right to left seen from outside (mirrored text); sphere, cylinder, cone and torus now put z = -sin, as the earlier framework's do.
69. **Apps' shaders are assets, packed beforehand and built at run time.** As the earlier framework did, an app writes GLSL that includes a framework block, which decides its kind and supplies the rest (`helix_screen`: the frame drawn over, its size, the time, the output; the vertex stage is the framework's). `tools/pack_shader.py` adds the framework's half, compiles it with the pinned sokol-shdc for both dialects, and writes a `.hxshader` (JSON: both programs, the attributes, uniform blocks with their members' std140 offsets read from the source, textures); examples' `shaders/*.glsl` are packed into their assets as they build, and again as they change in dev, so an edit reloads in the running page. `Shaders` loads them through the assets, and the adapters build the program from the file's data (`IGraphics.createShader`: sokol's shader desc filled from it; WebGL2 links the GLSL ES and looks up the names). Uniform blocks 0 and 1 and texture 0 are the framework's; an app's parameters are blocks from binding 2, set by name (`ScreenEffect.setFloat`, `setValues`, `setColor`) and kept across reloads. A Screen pipeline draws one triangle over the viewport (`drawScreen`); `PostProcess` draws a scene into a target, chains the effects through two more, and presents the last into the screen's pass. Built in at compile time was the alternative: typed parameters and simpler adapters, but a native rebuild for each edit and no shaders as data.
70. **Surface shaders: a Stage3D material's own fragment stage, and a vertex hook.** The `helix_surface` kind gives an app's fragment stage what the stage's lit shader has (the material's base color and textures, the normal-mapped normal, the camera, ambient light and lights, the time) as functions, the stage's own shading as `helix_shade`, and `helix_output` (tone map, then sRGB); the framework's vertex stage is the lit one, calling the app's `helix_vertex(inout position, inout normal)` when its file has a `@block vertex`. `Material.setShader` takes one, its parameters set by name through the same `ShaderParameters` a `ScreenEffect` has; Stage3D draws such runs through a pipeline per shader (made again when it reloads), passing its two blocks with the time after them. `drawMesh` now takes textures, samplings and uniform blocks by slot, as `drawScreen` does, so the framework's lit program and an app's draw the same way. Materials can be double sided (`Material.setDoubleSided`, and glTF's `doubleSided` is now read): a Lit3D pipeline without culling, whose shader turns the normal by `gl_FrontFacing`. Not yet in a surface shader: shadows and environment lighting (milestone 4), so the earlier framework's water reflects the sky as a color rather than an environment.
71. **Cameras can be nodes.** `Node.camera(camera)` places a `Camera3D` in a stage's tree: it sees from the node's world position down its -z, its +y up, so a camera parented to a car follows it and `lookAt` aims it. The camera is still what a draw is given (`Stage3D.draw`, `Batch3D.begin`); on a node, its view is worked out from the node's world matrix, computed afresh up its parents (`Node.computeWorld`) so the stage's dirty flags are left to its walk. The stage's root transform now places everything on the stage, as any parent's does (it was ignored).
72. **glTF from .gltf files, and from files beside them.** `Gltf.read` takes a GLB or a .gltf (its JSON); a buffer inside the file (the GLB's BIN chunk, or a base64 data: URI) is read at once, and one in a file of its own is fetched by `Models` through the assets, beside the model, before the model is built. Images likewise come from a buffer view, a data: URI, or a file beside the model; that last kind loads through the `Textures` service, so it reloads when the file changes, as any texture does. Each image is decoded once however many materials use it. A uri is resolved against the model's path, its %-escapes decoded and its ".." segments followed, and refused if it isn't a relative path inside the assets. The examples' car is now Kenney's Car Kit sports car (CC0), whose texture is such a file; the model example's copy has two headlight spot lights added in Blender and exported as a .gltf with a separate buffer, so it loads every kind of file beside a model; the generated toy car stays as the unit tests' fixture for glTF lights, BLEND and emissive materials.
73. **Mirrored models keep their faces.** A placement whose matrix has a negative determinant (an odd number of negative scales) turns a mesh's triangles clockwise, so Stage3D marks such a model mirrored, keeps it in runs of its own, and draws it through a pipeline whose front faces are the clockwise ones (`createPipeline`'s `clockwise`); inside a flipped target pass the adapters' twin turns that over again. Normal maps already followed mirroring through the tangents' sign in the instance record. A program's pipelines are now eight: blended or not, double sided or not, mirrored or not.
74. **Textures are shared by file.** Loads of the same path with the same filter share one `Texture2D`, counted: a load while another is under way joins it (one fetch, one decode, one upload), a later one is given the texture loaded, and `release` frees it with the last load's release. Models whose images are one file beside them (a kit's shared texture, a character's gear pieces) so share it on the GPU. Its sampling, being the texture's, is shared too. Materials stay per model file: they cost a few values each, alike ones from different files couldn't draw together anyway (a run needs one mesh), and merging them behind the game's back would surprise one that changes a material.
75. **3D sprites: wgrender-c's instanced quads.** `Node.sprite(texture)` is a textured quad on a Stage3D: a texture region, a size in world units, a pivot, a tint, a facing (the camera; upright, turning about y; flat on the ground; or as its node is turned) and an alpha mode (opaque, masked by a cutoff, blended, added). A framework program, `sprite3d`, follows wgrender-c's: an instance's record is where its pivot goes and its facing, its size and pivot, its region, its own axes and alpha mode, and its tint (96 bytes); the camera-facing axes are uniforms, worked out once a draw, so the CPU writes no matrix per sprite. One shader serves every alpha mode (a per-instance cutoff, or opaque, or as is); the pipeline gives the blending, so `createPipeline` takes a `BlendMode` (opaque, alpha, additive) in place of its alpha flag. `Sprites3D`, the stage's helper, sorts them: opaque and masked ones by texture after the opaque models, blended ones back to front among the see-through models, added ones last; each run of a texture is one instanced draw. Sprites are unlit, as 2D sprites, their colors sRGB values. WebGL2 has no base instance, so the instance binding is offset per draw as the lit models' is (wgrender-c read records from a float texture instead).
76. **3D text is sprites, a glyph each.** `Node.text3d(text, size, color, font)` lays a line out with the font's advances and kerning (the stage's built-in distance-field font, or a loaded one) and draws each glyph as a sprite3d instance in the text's plane: the camera's (worked out once a draw), upright, flat, or its node's as turned, its block placed by its pivot. The sprite program gained the 2D batch's distance-field branch, marked the same way (the tint's alpha over 1.5), so text stays sharp at any distance. Text is blended among the see-through models back to front, a text's glyphs together. The earlier frameworks drew it through fontstash in immediate mode; here it is one more run of instanced quads.
77. **Particles: wgrender-c's birth records, evaluated on the GPU, in 2D and 3D alike.** An `Emitter` (helix.particles) decides each particle when it's born (where and when, its velocity and life, its size scale, spin, starting angle and a random value: 48 bytes) and never touches it again; the `particle3d` program's vertex stage works out its place, size, color and turn from its age (gravity and drag, size and color curves of up to 8 keys, a palette, spin or stretch along the motion, flipbook frames), including wgrender-c's way around Adreno's driver failing to link a dynamically indexed uniform array. An emitter keeps a ring of records (the newest replacing the oldest past its maximum) and is one instanced draw. A node places it (`Node.emitter`, `Node2D.emitter`); the stage advances it by the stage's clock (`setTime`), the difference since its last draw, so emitters need no callbacks: they are a visual effect, drawn, and the game's state stays outside the tree. In 3D, Stage3D draws opaque ones after the opaque sprites, blended ones back to front among the see-through models and sprites, added ones last. In 2D they draw through the GPU too, not on the CPU: `Batch2D.emitter` makes a draw of its own a step in the batch's sequence, so particles keep their place in the stage's painter's order, their projection the 2D camera's with clip z at the near plane (no 3D depth drawn earlier hides them). One implementation of the particle math serves both.
78. **Shadow maps: the earlier frameworks' design, with the sun's texels held still in the world.** A directional light or a spot casts (`Light.setShadowCasting`; a point light would need six maps and is refused); models cast and receive unless told not to (`Node.setShadowCasting`, `setShadowReceiving`), see-through ones never cast. Each casting light, of the four a stage lights by, has a layer of one depth array (`IGraphics.createShadowMap`, a layer a pass: `beginShadowPass`), drawn by the `Depth3D` kind: Lit3D's vertices read at their own offsets (the shader manifest now takes a buffer's `stride`), a placement record a caster, casters alike in mesh one draw, culled against the light's view, nothing culled by face. Lookups are the earlier frameworks' to the letter: bias in texels (1 constant, 4 by slope), the map read a texel or so along the normal (more where the light grazes), a spot's slack converted at each fragment's own distance (one conversion lifted a thin caster's shadow 2.2 units off its foot), 3x3 comparison filtering, a fade over the map's last tenth, and no branch around the reads (Adreno). Measured in the browser with a 0.2-unit pillar seen from above: the shadow starts at the first floor pixel past it under the sun and under a spot (under 0.007 units; the earlier framework's test allows 0.12). Where HeliX differs: the sun's map is sized by the bounding sphere of what the camera sees out to the shadow distance, and snapped in a light space fixed to the world's origin, so its texels keep their size as the camera turns and their place as it moves; the earlier frameworks squared the slice's box in a light space that slid with the camera, so their snapping still let edges crawl (a unit test now holds a point's texel phase across camera moves). Shadow passes come before the screen's (sokol can't nest passes, and the app owns the frame), so an app calls `stage.drawShadows(camera)` before `beginFrame`, and draws read the maps it made last. The WebGL2 adapter checks a framebuffer once, when it's made: the per-pass check that cost the earlier framework 10 ms a pass in Chrome isn't there to remove. Surface shaders receive (`helix_light` takes the normal and returns shadowed light, so a custom lighting loop gets them unasked); they cast through the framework's depth program, so a vertex hook's movement and a fragment's discard don't reach their shadows yet (the water and dissolve spheres cast whole spheres).
79. **Environments: the earlier frameworks' split-sum light, prepared on the CPU a step at a time.** An environment map is an equirectangular image (a Radiance .hdr, read by HeliX's own reader, or a PNG or JPEG through `IImages`, from sRGB) that `EnvironmentBake` turns into what the earlier frameworks made: its irradiance as 9 spherical-harmonic coefficients, a background cube at the image's own resolution (width over 4, a power of two, box-filtered mips for blur) and a 128-pixel cube GGX-prefiltered a mip a roughness step (96 samples a texel, filtered importance sampling), both RGBA half floats (`TextureFormat.Rgba16f`, `IGraphics.createCubeTexture`); and once, for every environment, the split-sum BRDF table (64 square, computed rather than baked into the source: a million cheap iterations, done in the first bake's steps). CPU, not GPU, as the earlier frameworks chose: the same result on every backend, no float render targets (WebGL2 renders into half floats only with an extension), a thin graphics interface (one cube upload, no cube-face passes), and the math unit tested on the interpreter. The earlier frameworks prepared it on a worker thread natively and in steps on the web; HeliX has one stepped bake on both, run by the host's `Environments` service within a budget each frame (`poll`, 4 ms to start), one environment at a time, so a load never stalls a frame and needs no thread in shared code. Measured in user cycles on one pinned core (the host's clock was clamped, so not in milliseconds): a 1K .hdr's bake costs the earlier frameworks' C 1.04 billion cycles, HeliX's hxcpp 1.12 billion (1.08 times) and V8 1.92 billion (1.85 times), all three giving the same cubes to within float rounding; at full clock, about 0.3 s native and 0.6 s in a browser. Tied to the frame budget, a load takes longer the lower the frame rate (on the private display's 11 to 16 FPS software GL, over a minute); a native worker would cut that to the bake's own time. A stage lights its lit models by one (`setEnvironment`: intensity, a turn about +y) on top of its lights and ambient light (diffuse from the irradiance, specular from the prefiltered cube through the BRDF table, as glTF viewers light), draws one behind everything (`setBackground`, blur 0 to 1) through the `Background3D` kind (a framework program drawing one triangle at the far plane, depth-tested less or equal, drawn by `drawScreen`), and maps its lit color into 0..1 by an exposure in stops and a tone mapping (`setExposure`, `setTonemap`: Khronos PBR Neutral, ACES or none; Neutral at 0 EV is what the lit shader always did, so other examples look as before). Surface shaders get the same (`helix_shade` adds the environment; `helix_environment_irradiance`, `helix_environment_reflection` and `helix_environment_brdf` for their own lighting); the environment cube and BRDF table take bindings 3 and 4, so an app's own textures start at 5 and the native adapter takes 12 textures a program. Checked: the bake's unit tests (mappings both ways, the irradiance of a constant and a linear sky against the analytic answer, constant cubes staying constant, prefiltered mips keeping their energy, half floats against IEEE's, .hdr decoding flat and run-length encoded, the BRDF table's Schlick split, bound and Unreal's (0.72, 0.02) at its middle); and the browser's background against a reference made straight from the .hdr (2.8 levels of 255 mean difference; a mirrored mapping matches no camera angle better than 24).
80. **Adapters are a HAL; the graphics contract is data.** `IGraphics` listed HeliX's own pipeline kinds, so each adapter hardcoded every framework program's layout, texture slots and state (the WebGL2 adapter named the generated layouts 141 times, the C adapter branched per kind), and a new kind meant editing both. It is now resources, programs built from a `ShaderSource`, pipelines made from a `PipelineDesc` and one `draw`; the shader generator emits each framework program's sources and buffers' layout as Haxe (no C header, no program compiled into the native binary), `Pipelines` describes, makes and keeps the framework's pipelines per GPU (and rebuilds a framework program whose source changed in a browser hot reload, which the WebGL2 adapter did before), and drawing code asks it at each draw. Another GPU adapter (WebGPU, Vulkan, SDL3's) implements the contract alone. sokol's write-transient images (this sokol's only per-frame writable images) keep their contents a frame, so the native adapter keeps a data texture's copy and writes it at the first use of a frame, hiding the rule from the contract. `HostCore` builds the shared services, runs a frame in their order and closes them for both hosts, and now also releases the pipelines and shuts the GPU down, which neither host did. The rule and the audit of every other adapter are in ARCHITECTURE.md and ADAPTER_AUDIT.md; the audit's plan (host, shared async plumbing, fetch, storage, images, audio, input, enforcement) follows. Checked: the typecheck of every example on both targets, the unit tests, the services checks on both targets, ten examples in headless Chrome and seven natively on the private display.
