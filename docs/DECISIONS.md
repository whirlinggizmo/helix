# Decisions

Decisions are chronological. Entries 21 onward supersede the earlier SDL2 and minimal-loader choices; preserved SDL2 measurements are historical, not the current implementation.

1. Separate experiment05; no edits to prior experiments, shared documents or libwgf. Read the comparison plan and new brief/start prompt before implementation. Use only the prior experiment's pinned third-party Sokol headers as a read-only build dependency.
2. Shared Haxe owns game simulation and all rendering decisions. Compile-time classpaths supply `Platform`/`GraphicsBackend` with matching interfaces. There are no target conditionals in the shared sources. Native bindings, C resource calls and browser extern calls are confined to adapters.
3. Use a small subset of real Sokol operations, one fixed 32 B position/UV/color vertex record and one textured-color shader. One prepared expanded triangle batch is appropriate for this ordinary Asteroids slice; avoid introducing scene policy into the HAL or promising a complete multi-backend GPU framework.
4. Generate both shaders from one authored annotated GLSL file using pinned sokol-shdc. Native initial backend is GLCORE, browser WebGL2. Metal/Vulkan/WebGPU requires new builds and execution; shader generation alone is not portability proof.
5. Use original generated bitmap glyphs and colored geometry with one atlas. No art/files/services are taken from libwgf. Title/game-over screens are simple shared-renderer text, not a substitute claim for Clay or a reusable layout system.
6. Fixed-point positions/velocities and an integer heading table avoid repeating the prior simulation-trigonometry issue. RNG and replay are shared Haxe. Geometry additionally hashes actual float32 bytes. Live play uses fixed 60 Hz accumulation with bounded catch-up; benchmark replay uses exactly one step per delivered frame and reports cadence separately.
7. Common Haxe creates reusable float32 sound clips. Browser Web Audio unlocks after user input; native SDL2's audio device mixes copied clips, with16 voice slots. Native audio cannot be called an audible-output pass from a dummy device; browser/network audio streaming is not exercised. Missing device is reported and does not stop graphics.
8. Three CPU trials per target, sequential and uninstrumented; frozen audit/image checks separate. Record actual program totals with full Haxe DCE/analyzer and Terser, same per-file gzip9/Brotli11, page included. Include diagnostics instead of presenting an unverified hypothetical production minimum.
9. Local startup clocks exclude browser download/script evaluation before Haxe entry; native clock includes window acquisition. Do not infer matched cold startup or a native speed advantage from them. Dynamic native dependencies and their exclusions remain explicit.
10. Native input tooling holds a key until its state transition is observed rather than relying on a sub-frame pulse, finds its own window by PID, and forcibly cleans up when Sokol ignores SIGTERM. Diagnostic live writes are disabled in CPU cohorts. Authorized screen overrides restore exact prior state even on a failed check.
11. Context loss/device recovery, shader/resource breadth, further platforms, gamepads/touch, asset services, sustained GC/memory and feature-matched libwgf comparison remain follow-ups. The interface's first proof is one shared renderer serving two real adapters; size differences against another game are contextual, not a measured same-feature saving.
12. Parse sokol-shdc's structured `bare_yaml` reflection with pinned PyYAML6.0.1; never scrape generated shader/C text or select stale shader files by glob. Keep CPU packing roles/order in one small JSON schema because shader inputs do not specify buffer byte offsets. Generate Haxe inline layout constants and native C layout/binding metadata, validate cross-dialect agreement, and compile native static assertions against shdc's own constants. This is offline shader reflection, not Haxe runtime reflection. Reject unsupported schema/resource growth and test real compiler fixtures with relocated/renamed bindings before upgrading the pinned generator.
13. Move reusable contracts/utilities into `framework/hybrid`; retain the game in `src`. `IHost` composes independent `IInput`, `IAudio`, `IAssets` and `IGraphics` services; experiment hooks move to `IDiagnostics`. An independent consumer type-checks contracts and runs input/autopilot under interpreter/JS without game/adapter/generated-shader classpaths. No package manifest or publication is implied.
14. Normalize physical key names, primary framebuffer-pointer coordinates and mapped controller buttons/axes in adapters; action/dead-zone/menu policy stays shared. Preserve keyboard/pointer edges until a fixed tick consumes them. Clear input on focus loss, pause live simulation and stop thrust. Browser Gamepad API fixtures and an actual SDL virtual controller verify mappings; physical controllers remain untested. SDL supplies controller/audio services only, leaving Sokol as sole native window owner.
15. Load eight original PCM16 WAV files through a minimal asynchronous asset interface, decode/validate them in shared Haxe, and create copied PCM clips through `IAudio`. Browser uses fetch/Web Audio; native uses file-reading workers, host-thread completions and SDL mixing. This supersedes runtime synthesis in decision7. Native loader concurrency is adequate for this bounded slice, not a scalable asset manager. No streaming or audible-native-output claim.
16. Approximate representative reference gameplay/presentation with 960×720 layout, title rocks, clickable/focusable buttons, life icons/session best/extra lives, six-bullet cap, wave/respawn delays, varied rocks, particles and thrust looping. Keep independently authored fixed-point simulation, bitmap font, geometry and sound assets. This supersedes the simpler presentation in decision5 and some deferred items in decision11; it is still not a full equivalent ECS/prefab/UI port.
17. Record an intermediate service extraction with original game rules before gameplay growth. Its size delta includes exercised input/clip-voice capability, not just interface declarations. Final delivery separates code+HTML, eight sound files and optional autopilot/manifest. WAV encoding dominates current delivery; compressed audio is the next size gate. Shared framework/game continue to contain zero target conditionals.
18. Autopilot parses bounded versioned JSON commands into normal input, with explicit application probe callbacks. It uses ordinary Reflect only to validate JSON fields; no source scraping, private game-field reflection or game-state mutation. Full rendered browser/native playthrough matches 4584 ticks/outcomes/state/pixels. Fast mode is correctness tooling; the separate real-time replay remains the CPU cohort.
19. Keep HXML as compiler configuration and Python as external-tool orchestration. `helix.py` is the single build/test/check/autopilot/serve/measure/sizes/report front door; `Run.hx` optionally delegates from Haxe. Tooling stays outside runtime classpaths. A future haxelib can package the Haxe API and adapters, but native glue, shader generation and platform dependencies still need consumer-facing integration. See PACKAGING.md for actual checks and remaining package work.
20. Fractional text sizes exposed nearest-filter texel ties across browser/native GPUs. Apply one shared 0.01-texel glyph UV bias; the final five snapshots and autopilot image match RGB exactly. Do not relax image checks to hide a renderer difference. All latest correctness, CPU and autopilot evidence identifies the same artifacts; authorized screen overrides restore exact prior state.
21. Use Sokol app/graphics/audio as the executed native baseline. Add the exact pinned upstream sokol_audio header with its license inside this experiment. Sokol has no gamepad API; replace the SDL2 dependency with a small Linux evdev prototype, explicitly deferring physical-device and broad mapping validation. Dummy mixer/pipe tests and real ALSA callbacks are separate evidence. This supersedes the native choices in entries 7, 14 and 15. Preserve SDL2 and pre-fetch Sokol cohorts under results/archive/pre-helix/stages without inventing an unmeasured intermediate size.
22. Keep SDL3 in consideration for a complete native adapter: graphics, window/input, gamepads and audio, as explicitly requested. Interfaces allow independent or mixed selection. Desktop performance matters more than executable size; implementation and matched modern-backend/input/audio tests must precede a recommendation between native adapters. No SDL3 implementation/performance claim exists yet.
23. Split IFetch and IStorage mechanisms from shared AssetService. Callbacks expose completion, cancellation and progress, while bounded queues/workers and cooperative host pumping remain internal. Browser Fetch/ReadableStream and IndexedDB use native browser APIs, with no Wasm; native uses haxe.Http and file workers. Limit whole-file operations to 8 MiB and two active workers/transfers per adapter. A nominal 2 ms work slice cannot preempt a slow callback/decode/disk operation; large/direct-to-storage downloads are a future gate.
24. Define assets as encoded source files, resources as reusable runtime data, and instances as individual uses. AudioClip is decoded PCM, AudioStream is a progressively decoded source, AudioPlayback is one playing/paused instance. Releasing caller ownership retains a resource until all playbacks stop/finish. No persistent AudioSource/emitter is needed for this slice. Shared Haxe owns policy/lifetimes; browser media APIs and native Sokol own delivery mechanisms.
25. Streams check usable encoded storage first, using leased browser Blob URLs or native files, then browser remote media URLs. Remote playback does not persist; ensure first when persistence is required. Stored streams are not proof of network streaming. Native canonical mono PCM16/44100 WAV progressively feeds an 8192-sample float queue per playback; remote native streaming and codecs are explicit later gates. No simultaneous play-and-store path is claimed.
26. Run the same Haxe service suite on real browser/native adapters with isolated HTTP fixtures and two persistent-storage runs. Assert one ensured-WAV download per target across ensure/clip/stored-stream use; separately verify remote browser playback leaves the cache empty. Cover concurrency, progress, status, overflow, timeout/cancel/shutdown, committed storage, independent playback, pause/resume and final resource/source cleanup. An IndexedDB Blob must store only Bytes.length, not the spare capacity of a BytesBuffer backing array; the exact RIFF-length cache regression is tested.
27. Keep prototype limits explicit: cache identity is base URL/path rather than a versioned integrity manifest; no eviction/revalidation/deduplication; storage cancellation may leave a committed write; native cancellation is logical, native socket timeout differs from browser wall-clock deadline, redirects are not normalized and HTTPS has not executed. CPU game cohorts exclude service polling and do not measure concurrent streaming/download work. Refresh all current builds/cohorts/sizes after policy integration; preserve same-compressor accounting and exact screen restoration.
28. Add asynchronous `IAudio.decodeClip` beneath shared loading/lifetime policy. Browser Vorbis/Opus use Web Audio with owned input bytes; native uses a small libsndfile 1.2.2 bridge with pinned official SDK/license and a dynamic library, leaving Sokol PCM delivery unchanged. Normalize mono/stereo Ogg clip inputs to mono 44100 Hz; cap returned clip PCM at 8 MiB and use two native decoding workers. Native stored streams decode in chunks and rewind on loop. Keep host-fed queue underruns, decoder allocations, logical cancellation and native network streaming limits explicit. This supersedes the Ogg deferrals in entries17/25 without claiming MP3, stereo output or progressive network playback.
29. Encode the same eight independently generated WAV sources offline as quality 3 Vorbis; preserve source WAVs outside deployed assets. FFmpeg is tooling, not runtime. Opus is also supported and tested with a stereo 48 kHz fixture but is not needed in the game delivery. Retain pre-Ogg measurements in results/archive/pre-helix/stages/05-services-cohort and rerun identified game/service/image/CPU cohorts with the actual new artifacts. Same gzip9/Brotli11 accounting separates code from sounds; lossy encoding is not bit-identical audio equivalence.
30. Inspect reference checkouts read-only and inventory their public function declarations using Clang JSON AST, not source scraping. Record commits, clean/dirty state and exact input hashes, reject snapshots that change during extraction, and label all functions individually unverified. FEATURE_PARITY.md compares declared capabilities and proposes mixed submissions, UI, loading, multipass/3D, particles, scene/input and audio pressure probes. Do not infer full 1:1 parity or a web performance win from one atlas/shader/draw; no new physics implementation or root/shared-document edits are included.
31. Respond to weak/popping thrust feedback with an independently generated one-second circular filtered-noise/motor loop and more midrange energy, plus a shared tick-based volume attack/release. Keep the existing audio interface/adapters and version the filename as thrust-v2.ogg to bypass stored old bytes. Preserve the original Ogg cohort separately from this waveform/size change. Browser keyboard playback held one source beyond its duration, observed gain changes and stopped on release; signal checks and rebuilt browser/native correctness cohorts passed. Actual Chromebook speaker quality remains user feedback, and touch flight controls are deferred.
32. After the user confirmed v2 sounded better, lower the thrust motor tones from 160/320 Hz to 110/220 Hz and shift the circular noise filters down by enlarging their windows. Keep the duration and shared gain envelope. Use thrust-v3.ogg so persistent caches load the revised sound; preserve the preceding sound cohort in results/archive/pre-helix/stages/07-thrust-v2-cohort. Rebuild both targets and refresh the identified playback/correctness/size measurements; speaker preference still comes from listening feedback.
33. The user found v3 too deep and noticed repetition. Use 133/266 Hz motor tones (approximately halfway in pitch), intermediate noise filters, remove the periodic gain pulse, and extend independently synthesized noise to two seconds with a 40 ms equal-power head/tail blend. Version as thrust-v4.ogg and retain v3 evidence separately. Read-only libwgf inspection found 380 Hz low-pass noise, a 20 ms baked blend, and one persistent loop at volume .45, without motor tones/gain pulsing; record source identity in thrust-reference.json. Longer noise increases asset size. Playback/signal checks do not prove an imperceptible repeat; listening feedback remains necessary.
34. The user accepted v4 as sufficient and added a matched libwgf Asteroids comparison, including identical audio/assets, to the backlog. Prioritize broader feature parity now: P1 mixed submissions is the next unexecuted graphics gate, followed by UI/passes and loading/combined Racer workloads. Keep the current independently authored game and historical evidence distinct from a future matched reference workload; record this checkpoint and acceptance criteria in FEATURE_PARITY.md.

34. Name the library **HeliX**, with lower-case `helix` packages and `helix.py` tooling. Move contracts into domain packages and all Haxe implementations into `src/helix/adapters/<service>/<provider>`. Keep example/game/shader/asset/autopilot sources in `examples/asteroids`; tests, native glue, tools, docs and pinned dependencies own distinct directories. This experiment supplies its own Sokol headers. Supersedes the layout/naming in entries 2 and 13.
35. Separate composition from the host adapter. `platforms/` contains service-selection profiles; `HostServices` injects interfaces and adapter lifecycle hooks into browser/Sokol host loops. Shared game interfaces require no target conditionals. Native host and graphics still share one actual Sokol context. Profiles are application build choices, not a new GPU abstraction or published package.
36. Keep historical evidence verbatim in `results/archive/pre-helix`; keep stable reference JSON in `results/references`. New completed cohorts are recorded once in immutable `results/runs`, with `latest.json` selecting each current workload. Scratch outputs/caches/binaries stay under ignored `build`. Preserve the browser database name and internal `hy_*` C ABI so this rename does not invalidate stored audio or gratuitously change native bindings.
37. Add triangle-aligned first-vertex draw ranges to the existing fixed-layout graphics contract. Reject negative/misaligned/out-of-upload/overflow offsets on both adapters. P1 begins with a distinct 4096-quad workload and an overlapping-alpha oracle, separate from Asteroids and separate audit/timing runs. Full P1 still requires broader correctness, repeated trials, native actual-call/allocator/memory evidence and sampler/uniform work.

38. Supersede the first HeliX layout’s root `native/` and `platforms/` directories. Put C sources, headers and per-service extern bindings beside their owning adapter under `src/helix/adapters/<service>/<provider>/internal/`. Host and graphics have separate C translation units and retain one shared Sokol window/context. Centralize current Linux archive/link metadata in `adapters/internal/SokolNativeBuild.hx`.
39. Use `helix.profiles.BrowserWebGL2Profile` and `NativeSokolGLProfile` for explicit service composition. Tiny per-target application launchers inject `IHost`; shared game/benchmark code does not select a platform or contain target conditionals. Native consistently names the hxcpp target; desktop is a device scope. Browser host/input use the DOM provider and fetch uses Fetch API. A future WebGPU adapter/profile can reuse browser services; SDL3 and WebGPU remain unimplemented.
