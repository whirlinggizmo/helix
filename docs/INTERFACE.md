# Shared platform contracts

Reusable contracts live in `src/helix/`. Shared game/rendering code calls them identically on both targets. Target launchers select named profiles and pass `IHost` into shared application code; framework/game sources contain no target conditionals. No adapter traverses entities, implements game menus or constructs batches.

## Graphics

`IGraphics` is a deliberately bounded subset of the established Sokol HAL.

| Operation | Contract |
| --- | --- |
| createTexture(width,height,rgba) | Copy tightly packed RGBA8 bytes synchronously; nearest/clamp sampler; return opaque integer handle |
| createBuffer(capacityBytes) | Transient vertex storage; capacity is fixed, multiple of 32 |
| createPipeline(alpha) | One generated textured-color shader; fixed vertex layout; optional straight-alpha blending |
| updateBuffer(handle,data,usedBytes) | Synchronously consume caller-owned prefix; once per buffer per frame, starting at offset zero |
| beginFrame(width,height,x,y,w,h) | Clear complete framebuffer, then select lower-left-origin viewport; no depth/MSAA |
| draw(pipeline,buffer,texture,vertices,firstVertex=0) | TRIANGLES, nonindexed; bind those resources and issue one draw; use a validated range within uploaded bytes |
| endFrame() | End pass and submit; platform host owns presentation |
| destroy(kind,handle) | Release caller-owned resource; shutdown only after resources are destroyed |

Vertex records are little-endian eight float32 values: clip-space position xy, UV xy, straight color rgba (32 B). UVs refer to the top-to-bottom caller-provided image rows; neither backend silently flips pixels. Blend is SRC_ALPHA / ONE_MINUS_SRC_ALPHA for RGB and ONE / ONE_MINUS_SRC_ALPHA for alpha. The first game uses one alpha pipeline, one atlas, one reused expanded triangle buffer and one draw. This tests shared ownership, not state-changing throughput. Unsupported format/layout/pass features cannot silently map to another behavior.

One authored annotated GLSL file is compiled by pinned sokol-shdc to browser GLSL and a native Sokol shader descriptor. Its `bare_yaml` reflection is parsed with PyYAML, not extracted from generated C/GLSL. Attribute types/names/slots, texture/sampler slots and the combined GLSL uniform name come from that metadata. CPU packing order and semantic roles are defined once in `examples/asteroids/shaders/vertex.json`; the build validates the reflected types and generates offsets/stride for shared Haxe and native C. Shader reflection cannot infer the application's buffer packing. Native generated static assertions also verify the descriptor's binding constants. Haxe uses inline constants; there is no runtime reflection.

This remains one fixed 32 B vertex ABI and one texture/sampler pair. Unsupported resources/formats, duplicate keys/slots and dialect disagreement fail the build. The upstream metadata has no schema version; the pinned compiler, strict validation and real compiler fixture tests form the upgrade boundary. No handwritten target shader twins. The first native backend is GL; changing shaders/backend to Metal, Vulkan or WebGPU requires a new executed gate.

Handles are context-local, positive and typed by the API operation; they must not be retained after destruction. Adapters reject invalid dimensions, capacities, prefix lengths, handles and draw ranges. Application data is trusted in-process memory, not an untrusted command stream. `destroy` accepts `texture`, `buffer`, or `pipeline`; a texture owns its Sokol image/view underneath. The native adapter owns the shared sampler/shader until shutdown.

## Host and diagnostics

`IHost` composes graphics, input, low-level audio, fetch, storage, assets, shared `AudioResources`, and diagnostics. It owns the window, callback loop, monotonic clock in seconds, framebuffer dimensions, pixel ratio, focus and quit capability. Services exist before the init callback. Common Haxe owns fixed-step simulation, menu/action policy, geometry, resource ownership, asset decoding and readiness. Browser uses DOM/rAF/Web Audio; native uses one Sokol app window, Sokol audio and a Linux evdev gamepad adapter. Native presentation happens after the Haxe frame callback returns.

`run(init,frame,cleanup)` initializes once, supplies elapsed seconds to frame callbacks and cleans up resources when the host closes. The game uses fixed 60 Hz updates with bounded catch-up, resets accumulated time while unfocused and stops thrust playback. `canQuit` is true on native and false in browser; browser `quit()` stops the loop without closing a tab. Browser audio additionally suspends on blur/visibility loss and resumes after a real gesture. Sokol suspended/resumed events update native focus, but OS suspend/resume has not been exercised. Browser page-hide cleanup and device/context recovery still need broader lifecycle testing.

`IDiagnostics` owns experiment options, inspect/publish/capture hooks and backend information. It is separate from input/audio and window behavior, though the current host implements it. Probe/state JSON and capture tooling remain in measured builds. These hooks are not a storage/network API.

## Input

`IInput` exposes named physical keys with `down`, `pressed`, `released`; normalized controller buttons with `padDown`/`padPressed`; left-stick axes and right trigger; and one primary pointer with position, held and press/release state. `consume()` clears edges after a simulation tick without clearing held state. Polling/render frames do not clear edges. A down/up pair between ticks retains both edges even if the key is no longer held; repeated keydown does not create another press. Focus loss clears held keys/buttons/axes and pending presses to prevent unintended resumed actions. No text-input/IME or rebinding service exists yet.

Browser maps `KeyboardEvent.code`, pointer events and the first connected standard-mapped Gamepad API controller. Native maps Sokol keyboard/pointer events and one Linux evdev controller using a fixed mapping. Sokol supplies no gamepad API. The evdev prototype has pipe-fed event/disconnect tests but no physical-controller verification or mapping database. Normalized axes are clamped to [-1,1]; right trigger is 0..1. Dead zones/action thresholds are shared game policy (`Controls.hx`), not adapter policy. Controller disconnect returns neutral state. Gamepad polling cannot preserve a physical press/release that happens entirely between samples; keyboard/pointer event edges can.

Pointer positions use top-left-origin **framebuffer pixels**, not CSS pixels. Browser converts client coordinates using the canvas rectangle and framebuffer size; native supplies Sokol coordinates. Shared `Menu` maps them through letterboxing to 960×720 design coordinates. Only a primary pointer is exposed; pointer support does not constitute multitouch flight/fire controls.

`InputState` provides the shared accumulator used by adapters and autopilot. Autopilot supplies normal input to the same game/menu code and observes explicit app probes. Its bounded JSON parsing uses `Reflect` for schema field checks, not shader or game-internal reflection. See [PACKAGING.md](PACKAGING.md).

## Audio

An **asset** is encoded source bytes identified by a path. An **audio resource** is reusable playback data. `AudioClip` holds fully decoded PCM; `AudioStream` holds a progressively decoded source. `AudioPlayback` is one playing or paused instance. Streaming describes delivery/decoding, not where the encoded source lives: a stream can use a stored file or a remote URL. There is no separate audio player object or persistent spatial emitter in this slice.

Use shared `AudioResources.loadClip(path, callback)` or `loadStream(path, callback)`, returning `Ready(resource)`, `Failed(message)` or `Cancelled`. These return an `IRequest`. `play(resource, loop, volume)` returns an independent `AudioPlayback` with `stop()`, `pause(paused=true)`, `setVolume()` and `finished`. `resource.release()` drops the caller's ownership once; active playbacks retain it until stopped or naturally finished. A released resource cannot start another playback. Pausing retains the resource and any source lease. The host polls natural completion and shuts down resources before the backend.

`loadClip` requires a successfully ensured encoded asset, then calls `IAudio.decodeClip(encoded, callback)`, returning `Decoded(monoFloat32Bytes)`, `Failed(message)` or `Cancelled` through a cancellable request. The adapter selects its decoder; shared Haxe owns loading policy and lifetimes. Canonical WAV decoding remains the shared `Wav` utility; Ogg codecs sit beneath the adapter. `loadStream` resolves usable storage first, then a remote URL. Browser storage supplies a leased Blob URL; remote playback uses an audio element without storing the download. To guarantee storage, call `assets.ensure()` before `loadStream()`. No simultaneous play-and-store path is implemented. Service network counts prove each ensured WAV/Vorbis/Opus fixture downloads once across cache reads, clips, streams and a second process/page.

`IAudio` remains the mechanism interface beneath that policy: asynchronously decode encoded audio; copy mono float32 PCM at 44100 Hz into a clip; create a stream asynchronously from `AudioLocation`; play/stop/pause/setVolume/isPlaying; destroy clips/streams; poll and shut down. Handles are backend-local implementation details (native stream resource IDs are negative). Playback ID 0 means locked, unavailable or capacity exhausted and yields an already finished playback. The typed resource layer owns destruction; applications should not mix direct handle destruction with its lifetime methods.

Browser Ogg clips use `decodeAudioData` with an owned ArrayBuffer prefix, preserving stored/caller bytes when the browser consumes its input. Web Audio may decode at the existing context's device rate; the adapter downmixes mono/stereo and normalizes to mono 44100 Hz. Clips use buffer sources/gains; streams use `HTMLAudioElement` through Web Audio. Both Ogg/Vorbis and Ogg/Opus ran in Chromium; this does not establish every browser's codec availability. Decoder rejection reports failure. Browser decoding is asynchronous, but normalization/copying runs on the host thread and is not preemptible.

Native uses a thin C **libsndfile 1.2.2** bridge for Ogg/Vorbis and Ogg/Opus, beneath the Sokol mixer. Only these Ogg subtypes are accepted by this bridge. Mono/stereo sources with rates 8000–192000 Hz downmix and linearly resample to mono 44100 Hz; decoder PCM need not match browser PCM bit for bit. Two native workers decode clips, completing on the host. Each encoded input and normalized clip PCM caps at 8 MiB; this bounds returned PCM, not the internal allocations of a browser/library decoder. Logical cancellation delivers one terminal result and suppresses late completion; it cannot interrupt browser decoding or a native codec call already running.

The native mutex-protected Sokol mixer has 32 clip slots, 16 playback slots and device-rate resampling. Stored streams read canonical mono PCM16/44100 WAV or incrementally decode mono/stereo Vorbis/Opus into an 8192-sample mono float ring per playback. Codec state is per playback and rewound on loop; it is closed on stop/error/EOF, while the source lease remains until queued data drains. Host fills use up to 2048 samples per chunk and a nominal 2 ms per-stream slice; disk/codec calls can exceed it. Underruns produce silence and retain playback; EOF finishes after queued data drains. The device mixer runs independently, but a host stall beyond queued audio (~186ms at 44100 Hz when full) can interrupt a native stream. This differs from native reference decoding on the audio thread and needs a stall workload. A direct stored source is not subject to whole-file fetching's 8 MiB cap.

This is streaming decoded chunks from a stored file. Native remote streams explicitly fail with an instruction to ensure first. Browser remote fixture playback/cleanup passed, but the small fixtures do not prove playback starts before network EOF. Slow-network startup, native network streaming, general WAV layouts and MP3 remain separate gates.

The existing shared WAV clip decoder also has a stricter four-second PCM16 data limit; longer canonical WAV can use the stored stream path. Ogg clips instead use the normalized PCM byte cap. These are current prototype limits, not a general audio library specification.

Asteroids now delivers eight quality 3 Vorbis files made from its original generated WAV sources using offline FFmpeg. It plays fully decoded clips. The revised thrust-v4 asset is a two-second circular noise/motor loop; shared game code applies a tick-based volume attack/release through existing setVolume calls. This is game policy, not a general sample-accurate fade API. Separate fixtures exercise WAV/Vorbis/Opus clips and streams, including stereo 48 kHz Opus input, malformed/empty files and decode cancellation. Real ALSA callbacks and PCM mixer assertions ran; checks do not establish audible output quality. Stereo **output**, pitch/pan/seeking, segments, buses, fades, spatial audio and richer playback-error reporting remain unfinished. SDK pin/license and the external native decoder dependency are recorded in README/dependencies.json; no decoder is shipped in browser Wasm.

## Assets

`AssetService` implements `IAssets` using independently replaceable `IFetch` and `IStorage`. `ensure(path, callback, ?progress)` returns `IRequest` and later `Loaded(Bytes)`, `Failed(message)` or `Cancelled`. It checks encoded storage first, fetches or reads packaged bytes on a miss, and reports success only after a committed storage write. Progress contains a phase (locating/downloading/storing/ready), received bytes and nullable total. The compatibility `load()` delegates to ensure. `streamSource()` resolves a leased local source before a remote URL without ensuring or downloading it. Assets are source files; textures/clips/streams are runtime resources; playback/model placement are instances. A future glTF asset can produce mesh and texture resources without reversing that direction.

Paths reject schemes, absolute names, traversal and unsupported characters. Storage keys hash the asset base URL plus path; this separates hosts, but does not provide content versioning, integrity manifests or freshness validation. Browser uses IndexedDB encoded Blobs; native uses files with sibling temporary writes and replacement. Native packaged assets are under the executable's `assets/`; cache defaults to sibling `cache/` and can be overridden with `HELIX_CACHE`. This is a prototype cache, not a user-data sandbox or production platform cache-location policy. Storage quotas/errors fail explicitly; ensure does not silently bypass failed persistence.

## Fetch, scheduling and cancellation

`IFetch.fetch({url, ?maxBytes, ?timeoutSeconds}, callback, ?progress)` reports `Response({status,headers,bytes})`, `Failed(message)` or `Cancelled`. HTTP error statuses are responses; asset policy rejects non-2xx statuses. Defaults are 8 MiB and 15 seconds. Storage whole-file reads/writes also cap at 8 MiB. Browser uses Fetch/ReadableStream/AbortController, coalescing byte progress; native uses `haxe.Http` workers and samples byte progress under a mutex. There are at most two active fetch workers/transfers and two storage workers per adapter. Headers are lowercase; total bytes can be unknown, including content-encoded browser responses.

Callbacks run later on the host thread through `poll()`. Shared `WorkQueue` nominally processes 2 ms per poll; it cannot preempt a callback, decode, allocation, browser API or disk operation. This is cooperative scheduling, not a hard frame-time guarantee. Whole downloads are incrementally received but still assembled in memory; large/resumable downloads directly into storage, backpressure and frame-time profiling need a separate gate.

Cancel/shutdown deliver one terminal cancellation and suppress late completion. Browser aborts its network request; native cancellation is logical and a blocking worker retains its slot until completion/timeout. A storage operation already running may still commit after cancellation. Cancellation does not undo a completed write or cancel a terminal result already queued for delivery. Browser timeout is a wall-clock transfer deadline; native `haxe.Http.cnxTimeout` is a socket/inactivity timeout. Redirect and timeout behavior are not normalized across targets. Local HTTP fixtures ran; native HTTPS has compiled but is not yet an executed interoperability claim. No public task polling is required: callbacks expose completion/progress, while bounded queues stay beneath the interfaces.

## Deferred scope

SDL3 is a candidate for a complete native platform adapter: graphics, window/input, gamepads and audio. Services can be selected independently, including mixed Sokol/SDL3 configurations; a second backend must preserve resource/lifetime/input/shader contracts and run the same tests. No SDL3 backend or matched SDL3 performance result exists yet. Desktop performance takes priority over executable size. A comparison must include shader generation and executed modern graphics, not infer behavior from available APIs.

Multiple shaders/vertex layouts, index/instance buffers, explicit samplers, render targets, depth, shader resource/uniform layouts, context/device recovery, modern native adapters and WebGPU remain graphics gates. Asset manifests/versioning/revalidation, eviction/quotas, concurrent ensure deduplication, large downloads, normalized HTTPS/redirect/deadline behavior, remote native streaming, further codecs/playback controls, user-data storage, multitouch and text input remain service gates. [FEATURE_PARITY.md](FEATURE_PARITY.md) maps these gaps to the reference capabilities and proposed stress workloads. Add operations for exercised needs; this remains a thin interface over actual adapters.

## HeliX composition and range draws

Contract packages live under `helix.audio`, `helix.graphics`, `helix.input`, `helix.assets`, `helix.host` and `helix.debug`; `helix.core.WorkQueue` supplies cooperative callbacks. Haxe adapters live under `helix.adapters.<service>.<provider>`. The named compositions in `helix.profiles` inject `HostServices` into host adapters. `BrowserWebGL2Profile` selects WebGL2, DOM, Web Audio, Fetch API and IndexedDB; `NativeSokolGLProfile` selects the tested Linux native services. Lifecycle hooks let hosts poll input and handle focus/audio activation without importing a concrete service adapter. This does not imply that arbitrary native host/graphics contexts can be mixed. Native C sources, headers and per-service extern bindings live under their owning adapter’s `internal/` directory. Host and graphics use separate translation units with one shared Sokol context. `adapters/internal/SokolNativeBuild.hx` centralizes the current Linux archive/link integration. A WebGPU adapter/profile would reuse browser host/input/audio/storage services and implement its own graphics/device recovery; it has not been built.

`IGraphics.draw(..., vertices, firstVertex = 0)` draws a triangle-aligned range after one upload. Counts must be positive multiples of three; offsets must be nonnegative multiples of three and the complete range must fit the uploaded bytes. Both adapters reject oversized offsets without integer overflow. The existing Asteroids caller defaults to offset zero. P1 exercises distinct ranges, two blend pipelines and multiple texture handles; the fixed generated shader/layout remains application build output.

`IDiagnostics.frameCpu()` returns the previous host callback’s milliseconds, including service/input polling and application callback work. It excludes callback waiting and native presentation. It is an experiment metric, not a promised frame budget or GPU completion clock. See [MIXED_SUBMISSIONS.md](MIXED_SUBMISSIONS.md) for measured scope and remaining P1 gaps.
