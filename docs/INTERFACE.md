# Shared platform contracts

Reusable contracts live in `src/helix/`. Shared game/rendering code calls them identically on both targets. Target launchers select named profiles, which run an app on its `Services`; framework/game sources contain no target conditionals. No adapter traverses entities, implements game menus or constructs batches.

## Graphics

`IGraphics` is the GPU as a hardware abstraction layer: textures (2D, cube, data, render targets, depth arrays for shadows), stream and static buffers, programs built from a `ShaderSource` (both GLSL dialects and their bindings), pipelines made from a `PipelineDesc` (program, buffers' layout, primitive, indexing, blend, depth, culling and winding, depth-only, block 0's clip flip), passes (the screen's after any into targets and shadow maps) and one `draw`. Its doc comments are the contract. An adapter knows no program, layout or pipeline of HeliX's own: the framework's programs are generated from `src/helix/graphics/shaders/` (sokol-shdc compiles each; its `bare_yaml` reflection, checked against `shaders.json`, becomes a Haxe layout class with the program's `source()`, its `buffers()` and its packing constants), and `helix.graphics.Pipelines` describes, makes and keeps the framework's pipelines on each GPU. See [ARCHITECTURE.md](ARCHITECTURE.md).

Vertices and records are little-endian float32, laid out as the generated layouts say. UVs refer to the top-to-bottom caller-provided image rows; neither backend silently flips pixels. Blend modes: opaque; alpha, SRC_ALPHA / ONE_MINUS_SRC_ALPHA for RGB and ONE / ONE_MINUS_SRC_ALPHA for alpha; additive, the source times its alpha plus what's there. Handles are context-local, positive and typed by the operation; they must not be retained after destruction. Adapters reject invalid dimensions, capacities, prefix lengths, handles, uniforms and draw ranges. Application data is trusted in-process memory, not an untrusted command stream. The first native backend is GL; Metal, Vulkan or WebGPU are new adapters of the same contract, behind a new executed gate.

## 3D

`helix.render3d` is right-handed with +y up; distances are world units, angles radians. `Camera3D` is a perspective eye-and-target camera with GL clip depth and the same viewport and viewport-area model as `Camera2D`. `Mat4` is column-major, as shaders take it. Two modes, as the earlier frameworks had. Immediate: `Batch3D` draws triangles and lines (cubes, wire cubes, spheres, a grid) through the `Color3D` and `Lines3D` pipelines, shading solid shapes on the CPU by one directional light. Retained: a `Stage3D` holds `Node`s (groups, models of a `Mesh` and a `Material`, lights) and draws them through `Lit3D`: world matrices by dirty flags, the first four lights (directional, point or spot; a stage starts with none and no ambient light), each model's box culled against the view, the opaque sorted by material and mesh and the see-through back to front, one instanced draw a run. Materials are glTF metallic-roughness (base color and texture, metallic, roughness, a normal map and its strength, emissive light, lit or not), shaded by glTF's BRDF, lit by an environment map as well where the stage has one, and tone mapped (Khronos PBR Neutral, ACES or none, after an exposure); generated meshes carry tangents for the normal map. Shadows are DECISIONS 78, environments 79. The node rules are in DECISIONS 61.

Models come from glTF 2.0 files (GLB) through `Models`, in Haxe on both targets: a `ModelFile` holds the file's meshes (a part a primitive), materials and node tree, and `instantiate()` makes a node tree sharing them, its lights its own; parts are found once by their file names (`Node.find`). What a file uses that isn't read yet is listed by `ModelFile.getWarnings()`: skins and animations (a skinned mesh draws in its bind pose), morph targets, metallic-roughness, occlusion and emissive textures, alphaMode MASK, double-sided materials, texture transforms, a second texture coordinate set, and `.gltf` files with separate buffers.

## Host, runner and services

`IHost` is the platform's host and nothing more: it runs the loop (`run(init, frame, cleanup)`), keeps the clock, owns the window, quits, and passes run options (the URL query in a browser, `HELIX_*` environment variables natively). The `Runner` is what a host pumps, the same on every platform: at init it builds the app's `Services` over a profile's adapters (`Adapters`) and the engine's shared services over those; each frame it polls the shared services and input, runs the app's frame, ends input's frame and measures the frame; at cleanup it closes the shared services, the app, audio, input, the framework's pipelines and the GPU, in that order. An app never closes a platform service itself.

`Services` is what an app gets: graphics, input, audio, the window (with the drawing surface's size and pixel ratio, and focus: has the keyboard and is shown), assets, fetch, storage, sounds (`AudioResources`), textures, environments and the test harness, plus time, the frame's elapsed and CPU time, run options, quitting and backend facts. The runner fills it at init; an app keeps the object from its construction (`services -> new App(services)`) and reads it from `init` on. `IApp.frame(dt)` gets the frame's measured seconds, held between 1e-6 and 0.1 (`FrameClock`); `Services.getFrameElapsed()` is the unheld time a `Ticker` takes. The runner calls the app through the object each time, so after a hot reload its new methods are what run. `canQuit` is true natively and false in a browser, whose `quit()` stops the frames without closing the tab.

Focus is each adapter's own: the browser input adapter lets go of everything while the page is blurred or hidden, native input follows sokol's focus events, and Web Audio unlocks on the page's first key or pointer press and suspends while the page is blurred or hidden. `ITestHarness.publish` hands a check its result (`window.result` in a browser; a JSON line on stdout and the `HELIX_RESULT` file natively).

## Input

`IInput` exposes named physical keys with `down`, `pressed`, `released`; normalized controller buttons with `padDown`/`padPressed`; left-stick axes and right trigger; and one primary pointer with position, held and press/release state. `consume()` clears edges after a simulation tick without clearing held state. Polling/render frames do not clear edges. A down/up pair between ticks retains both edges even if the key is no longer held; repeated keydown does not create another press. Focus loss clears held keys/buttons/axes and pending presses to prevent unintended resumed actions. No text-input/IME or rebinding service exists yet.

Browser maps `KeyboardEvent.code`, pointer events and the first connected standard-mapped Gamepad API controller. Native maps Sokol keyboard/pointer events and one Linux evdev controller using a fixed mapping. Sokol supplies no gamepad API. The evdev prototype has pipe-fed event/disconnect tests but no physical-controller verification or mapping database. Normalized axes are clamped to [-1,1]; right trigger is 0..1. Dead zones/action thresholds are shared game policy (`Controls.hx`), not adapter policy. Controller disconnect returns neutral state. Gamepad polling cannot preserve a physical press/release that happens entirely between samples; keyboard/pointer event edges can.

Pointer positions use top-left-origin **framebuffer pixels**, not CSS pixels. Browser converts client coordinates using the canvas rectangle and framebuffer size; native supplies Sokol coordinates. Shared `Menu` maps them through letterboxing to 960×720 design coordinates. Only a primary pointer is exposed; pointer support does not constitute multitouch flight/fire controls.

`InputState` provides the shared accumulator used by adapters and autopilot. Autopilot supplies normal input to the same game/menu code and observes explicit app probes. Its bounded JSON parsing uses `Reflect` for schema field checks, not shader or game-internal reflection. See [PACKAGING.md](PACKAGING.md).

## Audio

An **asset** is encoded source bytes identified by a path. An **audio resource** is reusable playback data. `AudioClip` holds fully decoded PCM; `AudioStream` holds a progressively decoded source. `AudioPlayback` is one playing or paused instance. Streaming describes delivery/decoding, not where the encoded source lives: a stream can use a stored file or a remote URL. There is no separate audio player object or persistent spatial emitter in this slice.

Use shared `AudioResources.loadClip(path, callback)` or `loadStream(path, callback)`, returning `Ready(resource)`, `Failed(message)` or `Cancelled`. These return an `IRequest`. `play(resource, loop, volume)` returns an independent `AudioPlayback` with `stop()`, `pause(paused=true)`, `setVolume()` and `finished`. `resource.release()` drops the caller's ownership once; active playbacks retain it until stopped or naturally finished. A released resource cannot start another playback. Pausing retains the resource and any source lease. The host polls natural completion and shuts down resources before the backend.

`loadClip` requires a successfully ensured encoded asset, then calls `IAudio.decodeClip(encoded, callback)`, returning `Decoded(monoFloat32Bytes)`, `Failed(message)` or `Cancelled` through a cancellable request. The adapter selects its decoder; shared Haxe owns loading policy and lifetimes. Canonical WAV decoding remains the shared `Wav` utility; Ogg and MP3 codecs sit beneath the adapter. `loadStream` resolves usable storage first, then a remote URL. Browser storage supplies a leased Blob URL; remote playback uses an audio element without storing the download. To guarantee storage, call `assets.ensure()` before `loadStream()`. No simultaneous play-and-store path is implemented. Service network counts prove each ensured WAV/Vorbis/Opus fixture downloads once across cache reads, clips, streams and a second process/page.

`IAudio` remains the mechanism interface beneath that policy: asynchronously decode encoded audio; copy mono float32 PCM at 44100 Hz into a clip; create a stream asynchronously from `AudioLocation`; play/stop/pause/setVolume/isPlaying; destroy clips/streams; poll and shut down. Handles are backend-local implementation details (native stream resource IDs are negative). Playback ID 0 means locked, unavailable or capacity exhausted and yields an already finished playback. The typed resource layer owns destruction; applications should not mix direct handle destruction with its lifetime methods.

Browser Ogg and MP3 clips use `decodeAudioData` with an owned ArrayBuffer prefix, preserving stored/caller bytes when the browser consumes its input. Web Audio may decode at the existing context's device rate; the adapter downmixes mono/stereo and normalizes to mono 44100 Hz. Clips use buffer sources/gains; streams use `HTMLAudioElement` through Web Audio. Ogg/Vorbis and Ogg/Opus clips ran in Chromium in the service checks; MP3 is accepted the same way. This does not establish every browser's codec availability. Decoder rejection reports failure. Browser decoding is asynchronous, but normalization/copying runs on the host thread and is not preemptible.

Native uses a thin C **libsndfile 1.2.2** bridge for Ogg/Vorbis, Ogg/Opus and MP3 (libsndfile reads MP3 through mpg123 from 1.1 on), beneath the Sokol mixer. Only these formats are accepted by this bridge. Mono/stereo sources with rates 8000–192000 Hz downmix and linearly resample to mono 44100 Hz; decoder PCM need not match browser PCM bit for bit. Two native workers decode clips, completing on the host. Each encoded input and normalized clip PCM caps at 8 MiB; this bounds returned PCM, not the internal allocations of a browser/library decoder. Logical cancellation delivers one terminal result and suppresses late completion; it cannot interrupt browser decoding or a native codec call already running.

The native mutex-protected Sokol mixer has 32 clip slots, 16 playback slots and device-rate resampling. Stored streams read canonical mono PCM16/44100 WAV or incrementally decode mono/stereo Vorbis/Opus/MP3 into an 8192-sample mono float ring per playback. Codec state is per playback and rewound on loop; it is closed on stop/error/EOF, while the source lease remains until queued data drains. Host fills use up to 2048 samples per chunk and a nominal 2 ms per-stream slice; disk/codec calls can exceed it. Underruns produce silence and retain playback; EOF finishes after queued data drains. The device mixer runs independently, but a host stall beyond queued audio (~186ms at 44100 Hz when full) can interrupt a native stream. This differs from native reference decoding on the audio thread and needs a stall workload. A direct stored source is not subject to whole-file fetching's 8 MiB cap.

This is streaming decoded chunks from a stored file. Native remote streams explicitly fail with an instruction to ensure first. Browser remote fixture playback/cleanup passed, but the small fixtures do not prove playback starts before network EOF. Native network streaming, play-while-keeping on both targets and proof of slow-network startup are milestone 7 (README). General WAV layouts remain a separate gate. MP3 clips and streams are accepted on both targets (the `audio-music` example opens its music as an MP3 stream), but no check covers MP3 yet: the service checks have no MP3 fixture.

The existing shared WAV clip decoder also has a stricter four-second PCM16 data limit; longer canonical WAV can use the stored stream path. Ogg clips instead use the normalized PCM byte cap. These are current prototype limits, not a general audio library specification.

Asteroids now delivers eight quality 3 Vorbis files made from its original generated WAV sources using offline FFmpeg. It plays fully decoded clips. The revised thrust-v4 asset is a two-second circular noise/motor loop; shared game code applies a tick-based volume attack/release through existing setVolume calls. This is game policy, not a general sample-accurate fade API. Separate fixtures exercise WAV/Vorbis/Opus clips and streams, including stereo 48 kHz Opus input, malformed/empty files and decode cancellation. Real ALSA callbacks and PCM mixer assertions ran; checks do not establish audible output quality. Stereo **output**, pitch/pan/seeking, segments, buses, fades, spatial audio and richer playback-error reporting remain unfinished. SDK pin/license and the external native decoder dependency are recorded in README/dependencies.json; no decoder is shipped in browser Wasm.

## Assets

`AssetService` implements `IAssets` using independently replaceable `IFetch` and `IStorage`. `ensure(path, callback, ?progress)` returns `IRequest` and later `Loaded(Bytes)`, `Failed(message)` or `Cancelled`. It checks encoded storage first, fetches or reads packaged bytes on a miss, and reports success only after a committed storage write. Progress contains a phase (locating/downloading/storing/ready), received bytes and nullable total. The compatibility `load()` delegates to ensure. `streamSource()` resolves a leased local source before a remote URL without ensuring or downloading it. Assets are source files; textures/clips/streams are runtime resources; playback/model placement are instances. A future glTF asset can produce mesh and texture resources without reversing that direction.

`IAssets.subscribe(path, target:IReloadable)` asks for `target.reloaded(path, bytes)` when that file changes and has loaded again; `unsubscribe` ends it. `AssetService.changed(path)` does the loading, past the HTTP cache (`FetchRequest.noCache`) and the stored copy, and stores the new copy; only `-D hotreload` browser builds call it, from hotreload-hx's changed-file notices. A failed reload keeps what subscribers have and is listed in `reloads` (the host's `assetReloads` diagnostic). `AudioResources` subscribes for its clips and swaps a reloaded clip's backend clip in place.

Paths reject schemes, absolute names, traversal and unsupported characters. Storage keys hash the asset base URL plus path; this separates hosts, but does not provide content versioning, integrity manifests or freshness validation. Browser uses IndexedDB encoded Blobs; native uses files with sibling temporary writes and replacement. Native packaged assets are under the executable's `assets/`; cache defaults to sibling `cache/` and can be overridden with `HELIX_CACHE`. This is a prototype cache, not a user-data sandbox or production platform cache-location policy. Storage quotas/errors fail explicitly; ensure does not silently bypass failed persistence.

## Fetch, scheduling and cancellation

`IFetch.fetch({url, ?maxBytes, ?timeoutSeconds, ?noCache}, callback, ?progress)` reports `Response({status,headers,bytes})`, `Failed(message)` or `Cancelled`. HTTP error statuses are responses; asset policy rejects non-2xx statuses. Defaults are 8 MiB and 15 seconds. Storage whole-file reads/writes also cap at 8 MiB. Browser uses Fetch/ReadableStream/AbortController, coalescing byte progress; native uses `haxe.Http` workers and samples byte progress under a mutex. There are at most two active fetch workers/transfers and two storage workers per adapter. Headers are lowercase; total bytes can be unknown, including content-encoded browser responses.

Callbacks run later on the host thread through `poll()`. Shared `WorkQueue` nominally processes 2 ms per poll; it cannot preempt a callback, decode, allocation, browser API or disk operation. This is cooperative scheduling, not a hard frame-time guarantee. Whole downloads are incrementally received but still assembled in memory; large/resumable downloads directly into storage, backpressure and frame-time profiling need a separate gate.

Cancel/shutdown deliver one terminal cancellation and suppress late completion. Browser aborts its network request; native cancellation is logical and a blocking worker retains its slot until completion/timeout. A storage operation already running may still commit after cancellation. Cancellation does not undo a completed write or cancel a terminal result already queued for delivery. Browser timeout is a wall-clock transfer deadline; native `haxe.Http.cnxTimeout` is a socket/inactivity timeout. Redirect and timeout behavior are not normalized across targets. Local HTTP fixtures ran; native HTTPS has compiled but is not yet an executed interoperability claim. No public task polling is required: callbacks expose completion/progress, while bounded queues stay beneath the interfaces.

## Deferred scope

SDL3 is a candidate for a complete native platform adapter: graphics, window/input, gamepads and audio. Services can be selected independently, including mixed Sokol/SDL3 configurations; a second backend must preserve resource/lifetime/input/shader contracts and run the same tests. No SDL3 backend or matched SDL3 performance result exists yet. Desktop performance takes priority over executable size. A comparison must include shader generation and executed modern graphics, not infer behavior from available APIs.

Multiple shaders/vertex layouts, index/instance buffers, explicit samplers, render targets, depth, shader resource/uniform layouts, context/device recovery, modern native adapters and WebGPU remain graphics gates. Asset manifests/versioning/revalidation, eviction/quotas, concurrent ensure deduplication, large downloads, normalized HTTPS/redirect/deadline behavior, remote native streaming, further codecs/playback controls, user-data storage, multitouch and text input remain service gates. [FEATURE_PARITY.md](FEATURE_PARITY.md) maps these gaps to the reference capabilities and proposed stress workloads. Add operations for exercised needs; this remains a thin interface over actual adapters.

## Composition

Contract packages live under `helix.audio`, `helix.graphics`, `helix.input`, `helix.assets`, `helix.host` and `helix.debug`; `helix.core.WorkQueue` supplies cooperative callbacks. Adapters live under `helix.adapters.<area>.<api>`; their C sources, headers and extern bindings under the adapter's `internal/` directory, built by `adapters/internal/SokolNativeBuild.hx`. A profile in `helix.profiles` picks a host and an adapter for each contract and runs an app on them: `BrowserWebGL2Profile.run` (WebGL2, DOM, Web Audio, Fetch API, IndexedDB, the page's image decoder) and `NativeSokolGLProfile.run` (sokol on GL 4.1, sokol audio with libsndfile, evdev gamepads, haxe.Http, files, stb_image). The rule for what may live in an adapter, and its check, are in [ARCHITECTURE.md](ARCHITECTURE.md).
