# Shared platform contracts

Reusable contracts live in `src/helix/`. Shared game/rendering code calls them identically on both targets. Target launchers select named profiles, which run an app on its `Services`; framework/game sources contain no target conditionals. No adapter traverses entities, implements game menus or constructs batches.

## Graphics

`IGraphics` is the GPU as a hardware abstraction layer: textures (2D, cube, data, render targets, depth arrays for shadows), stream and static buffers, programs built from a `ShaderSource` (both GLSL dialects and their bindings), pipelines made from a `PipelineDesc` (program, buffers' layout, primitive, indexing, blend, depth, culling and winding, depth-only, block 0's clip flip), passes (the screen's after any into targets and shadow maps) and one `draw`. Its doc comments are the contract. An adapter knows no program, layout or pipeline of HeliX's own: the framework's programs are generated from `src/helix/graphics/shaders/` (sokol-shdc compiles each; its `bare_yaml` reflection, checked against `shaders.json`, becomes a Haxe layout class with the program's `source()`, its `buffers()` and its packing constants), and `helix.graphics.Pipelines` describes, makes and keeps the framework's pipelines on each GPU. See [ARCHITECTURE.md](ARCHITECTURE.md).

Edges are smoothed by multisampling, asked for before the window opens: a profile's `run` takes a `WindowOptions`, whose `requestMsaaSamples(count)` asks for 1 (none), 2, 4 or 8 samples a pixel, 4 when not given. It's a request: natively the window gets what the driver grants, in the browser any count over 1 turns the canvas's `antialias` on and the browser chooses how many (nearly always 4). `IGraphics.getMsaaSamples()` answers what was given, and `getMaxMsaaSamples()` the most a window could ask for here (natively the GPU's most, at most 8; in the browser the count the canvas has when antialiased), for a settings menu to offer and apply at the next start. Render targets are drawn with the screen's samples and resolved into the texture sampled at the pass's end, so they're as smooth as the screen; shadow maps are depth only and single-sampled.

Vertices and records are little-endian float32, laid out as the generated layouts say. UVs refer to the top-to-bottom caller-provided image rows; neither backend silently flips pixels. Blend modes: opaque; alpha, SRC_ALPHA / ONE_MINUS_SRC_ALPHA for RGB and ONE / ONE_MINUS_SRC_ALPHA for alpha; additive, the source times its alpha plus what's there. Handles are context-local, positive and typed by the operation; they must not be retained after destruction. Adapters reject invalid dimensions, capacities, prefix lengths, handles, uniforms and draw ranges. Application data is trusted in-process memory, not an untrusted command stream. The first native backend is GL; Metal, Vulkan or WebGPU are new adapters of the same contract, behind a new executed gate.

## 3D

`helix.render3d` is right-handed with +y up; distances are world units, angles radians. `Camera3D` is a perspective eye-and-target camera with GL clip depth and the same viewport and viewport-area model as `Camera2D`. `Mat4` is column-major, as shaders take it. Two modes, as the earlier frameworks had. Immediate: `Batch3D` draws triangles and lines (cubes, wire cubes, spheres, a grid) through the `Color3D` and `Lines3D` pipelines, shading solid shapes on the CPU by one directional light. Retained: a `Stage3D` holds `Node`s (groups, models of a `Mesh` and a `Material`, lights) and draws them through `Lit3D`: world matrices by dirty flags, the first four lights (directional, point or spot; a stage starts with none and no ambient light), each model's box culled against the view, the opaque sorted by material and mesh and the see-through back to front, one instanced draw a run. Materials are glTF metallic-roughness (base color and texture, metallic, roughness, a normal map and its strength, emissive light, lit or not), shaded by glTF's BRDF, lit by an environment map as well where the stage has one, and tone mapped (Khronos PBR Neutral, ACES or none, after an exposure); generated meshes carry tangents for the normal map. Shadows are DECISIONS 78, environments 79. The node rules are in DECISIONS 61.

Models come from glTF 2.0 files (GLB, or `.gltf` with its buffers and images beside it) through `Models`, in Haxe on both targets: a `ModelFile` holds the file's meshes (a part a primitive), materials and node tree, and `instantiate()` makes a node tree sharing them, its lights its own; parts are found once by their file names (`Node.find`). What a file uses that isn't read yet is listed by `ModelFile.getWarnings()`: morph targets (and their weights' animations), a second set of joints and weights, primitives other than triangles, metallic-roughness, occlusion and emissive textures, alphaMode MASK, texture transforms, a second texture coordinate set, and textures or images it can't find.

## Host, runner and services

`IHost` is the platform's host and nothing more: it runs the loop (`run(init, frame, cleanup)`), keeps the clock, owns the window, quits, and passes run options (the URL query in a browser, `HELIX_*` environment variables natively). The `Runner` is what a host pumps, the same on every platform: at init it builds the app's `Services` over a profile's adapters (`Adapters`) and the engine's shared services over those; each frame it polls the shared services and input, runs the app's frame, ends input's frame and measures the frame; at cleanup it closes the shared services, the app, audio, input, the framework's pipelines and the GPU, in that order. An app never closes a platform service itself.

`Services` is what an app gets: graphics, input, audio, the window (with the drawing surface's size and pixel ratio, and focus: has the keyboard and is shown), assets, fetch, storage, sounds (`AudioResources`), textures, environments and the test harness, plus time, the frame's elapsed and CPU time, run options and quitting. The runner fills it at init; an app keeps the object from its construction (`services -> new App(services)`) and reads it from `init` on. `IApp.frame(dt)` gets the frame's measured seconds, held between 1e-6 and 0.1 (`FrameClock`); `Services.getFrameElapsed()` is the unheld time a `Ticker` takes. The runner calls the app through the object each time, so after a hot reload its new methods are what run. `canQuit` is true natively and false in a browser, whose `quit()` stops the frames without closing the tab.

Input's focus policy is shared (below); an input adapter only reports focus: the window's focus and the page's visibility in a browser, sokol's focus events natively. Web Audio unlocks on the page's first key or pointer press and suspends while the page is blurred or hidden. `ITestHarness.publish` hands a check its result (`window.result` in a browser; a JSON line on stdout and the `HELIX_RESULT` file natively).

## UI

`helix.ui` is wgrender-c's model (widgets are nodes, read each frame) with libwgf's focus. A `Ui` over a Stage2D, its camera, a `Pointer` looking at that stage and the input makes widgets (`label`, `panel`, `button`, `toggle`, `slider`, `progress`, `list`, `textField`), each owning its nodes and a layout `Box`; `update()` once a frame after the pointer's; the app then asks (`isClicked`, `getValue`, `isChanged`, `getSelectedIndex`, `isActivated`, `isSubmitted`), nothing is called back (DECISIONS 61). `Box` lays out rows, columns and stacks (anchors), sizes fixed, fitted, growing by weight or a share, with padding, gaps and alignment, writing nodes' positions (by their pivots) and sizes once a frame (`Box.arrange`). Focus moves in the order widgets were made (Down, Tab, a pad's Down; Up, Shift+Tab; Left and Right unless a slider or text field takes them; a list takes Up and Down), Enter, Space or South activates, Escape or East is back; the ring shows only when keys or a pad moved focus; after keys or a pad something has focus; a key held into a new screen (`reset`) does nothing until let go; while a widget has the keys (`isCapturingKeys`, always for a text field) a game should leave them be. A `Panel` holds its widgets (`add`), hidden with it, its background a rectangle or a nine-slice frame. The `Theme` sets colors and sizes, among them `corner`, the radius rounding panels, buttons, fields, lists, tracks and bars (8 to start, libwgf's; 0 for square), which the focus ring follows. `Ui.press(name)` uses a widget by name as a click would, when it's shown and usable: tests and the autopilot's `click`. Beneath it: `IGraphics.setScissor`, Batch2D's nested clips and Stage2D nodes clipping their children (drawn and picked), nine-slice sprites, and wrapped text.

## Picking and the pointer

`Camera3D.computeRay(x, y, ray)` is the ray through a framebuffer pixel (from the top-left, as the pointer is) within the camera's viewport area, from its near plane, through the matrices the stage draws with (perspective or orthographic); false outside the viewport. `Stage3D.pick(camera, x, y, ?hit)` returns the nearest hit as a `PickHit` (the node, the distance from the near plane, the point in the world and in the node's own space, the normal facing back along the ray), or null; `pickAlong(ray, ?camera, ?hit)` follows any ray (sprites and text need the camera to face). Models are hit by their triangles from either side, after their world box (one beyond the nearest hit so far is skipped); a skinned model by its triangles as posed now, posed on the CPU with the GPU's blend; a see-through model (blended material or tint) only where its alpha reaches a half; 3D sprites and text by their quads as drawn (a text by its whole block), not yet by their texels; emitters never. `Stage2D.pick(camera, x, y)` returns the topmost node under a point by each kind's own area (a filled shape's area, a rounded rectangle's without the corners cut off, an outlined one's or a line's stroke, a sprite's rectangle, a text's block). Both honour the node flags: disabled skips the subtree, unpickable passes the node (its children still hit), hidden is still hit. Picks walk the tree as it is, so a gear swap changes the next pick.

`helix.scene.Pointer` is the pointer over stages, asked of, never telling the nodes (DECISIONS 61): stages are added in draw order with their cameras (`addStage3D`, `addStage2D`), `update()` once a frame after input picks them topmost first, and `isHovered`, `isPressed`, `isDown` (held, kept while dragged off), `isClicked` (released over what it was pressed on), `getHit3D` and `isCaptured` answer. A press on a 2D node captures the pointer until it's released: the stages under it see nothing. Edges last the frame they happen in; the pointer is sampled once a frame, so two clicks within a frame are one.

## Lights

A Stage3D considers the first 64 lights its walk finds (a hidden or disabled one isn't found). Each draw it scores every one against each drawn model's box, as libwgt did: its brightness (luminance of color times intensity), times its falloff at the box's nearest point (inverse square from 0.1 out, windowed to nothing at its range; nothing past the range), times a spot's cone at the box's center (unless the light is inside the box); a directional light scores its brightness everywhere. The 16 with the best score over the drawn models are the table the shaders read; each model is lit by the 8 of those that reach it most, named in its instance record, so models sharing a mesh still draw as one. The first four lights that cast have shadows. A surface shader's `helix_light_count()` and `helix_light(i, …)` are the model's own lights, 0 to the count less one.

## Node flags

Every node, 3D and 2D, has libwgf's three flags, each its own and on to start (but `pickable` for text, off until asked: a label lets picks through to what it's on): `enabled` (off: it and everything under it are skipped by drawing, picking and updates, an emitter under it not moved on; the only one reaching the children, whose own flags are kept), `visible` (off: its own output isn't drawn, a light doesn't shine or cast, an emitter still moves on; it stays placed and its children are as they are) and `pickable` (off: a pick's ray passes its own output; its children can still be hit). Drawing and picking don't depend on each other: hidden and pickable is a hit area.

## Skinning and animation

A glTF skin is read into a `Skin` (its joints by name, their inverse bind matrices) and each vertex's first four joints and weights (normalized to sum to 1; an unweighted vertex follows its first joint). Each copy of a file (`instantiate`) binds its skinned models to that copy's joints; `Node.bindSkeleton(skeleton)` binds a model to any skeleton with the same joint names, refusing (false, unchanged) one missing a joint, which is how gear from a file of its own goes on a character, and how it is swapped at run time. A skinned model's own placement doesn't move it (glTF's rule): its joints do. A socket is a node added under a joint (`character.find("Middle1.R").add(sword)`); it follows the joint like any child. Animations are read into `AnimationClip`s of `Track`s (translation, rotation, scale; linear, step and cubic spline), targeting nodes by name, so a file of animations alone (`getClips`, `getClip("Walk")` finding "CharacterArmature|Walk") plays on any skeleton with those names. An `Animator(root)` plays one clip at a time on the nodes under root, refusing a clip that moves a node root hasn't, crossfading over the seconds `play` is given (a node only one clip moves blends with its rest pose, where it stood when first bound); a play during a fade starts from the clip playing, dropping the one fading out. `Stage3D` draws skinned models through the skinned programs: every skinned model's joints of a pass go into one data texture (inverse(model world) × joint world × inverse bind, three texels a joint), its first joint in its record, uploaded once a pass (the shadow pass and the draw). A skinned model is culled by its joints as posed, each padded by the farthest vertex it weights and the box by 2% (a rest-pose box drops a limb swung outside it), after the walk has posed every joint. Not yet: animation layers, skinned surface shaders (a skinned model's surface shader is ignored), morph targets, more than four joints a vertex. Checked: `AnimationTests` (sampling, weights, the Quaternius files, binding and refusal, crossfades and rest blending, joint matrices, a limb posed out of its rest box still drawn); the `animation` example in Chromium (clips, crossfades, the outfit swapped, the sword socket, posed shadows).

## Screenshots

`Services.screenshots.take(?name, ?done)` saves the next frame the app ends: the `Runner` calls `frameEnded` after the app's frame, which reads the frame back (`IGraphics.readPixels(0)`, before the frame is presented: a browser can't read it after), encodes it with the shared `Png` (row filters, then deflate with LZ77 and the fixed Huffman codes, the same bytes on every target) and hands it to `IExport`: a download in a browser, a file natively in `HELIX_EXPORT`, else the user's pictures directory (`XDG_PICTURES_DIR`, else `~/Pictures`) under the product's name, else `exports/` beside the program. Files are named `<product>-<date>-<time>-<n>.png` unless named. `readPixels` also reads a render target, for shots at another size or pixel checks. Encoding runs on the host thread, so a screenshot's frame is slower. Checked: a static example's screenshot matches the window pixel for pixel natively (an X11 grab) and in Chromium (a page capture), alpha 255 throughout; the encoder round-trips through Haxe's own inflater. The examples take one on F9 (`examples/shared/src/DevKeys.hx`); autopilot scripts with `{"op": "screenshot", "name": "title.png"}`.

## Input

`IInput` exposes named physical keys (`isDown`, and the edges `isPressed`/`isReleased` per tick and `isFramePressed`/`isFrameReleased` per frame), mouse buttons with the same edges, one primary pointer (position, held, edges), the wheel, typed text, touches with a two-finger gesture (pan, pinch, twist), and four gamepad slots (`getPad`, and `isPadDown`/`isPadPressed`/`getPadAxis` over any connected pad). Tick edges are counted: `consume()` after a simulation tick takes one of each, so every press reaches exactly one tick and two presses between ticks reach two; frame edges, text, the wheel and lifted touches last one frame. Repeated keydown does not create another press. Focus loss lets go of everything held and drops pending presses, so nothing resumes by accident. Typed text is the characters after the keyboard layout; there is no IME composition or rebinding service yet.

An input adapter is an `IInputSource`: it reports its platform's events as they are (keys, text, mouse buttons, moves and leaving, the wheel, fingers, focus, and each connected pad's state at poll) to the shared `InputRouter`, which the `Runner` owns and whose `InputState` is the app's `IInput`. The router holds the policy once for every platform: the primary pointer is the mouse with its left button or the first finger down, a second finger letting it go until all lift (so touch drives the pointer natively too); losing focus lets go of everything, and while unfocused presses, text, the wheel and pads are ignored (pads stay connected, released and centred); text is dropped while Control or Super is held; the first four connected pads fill the four slots in the platform's order. Key codes are each adapter's table (sokol's codes are `Key`'s GLFW numbers, its right-hand modifiers folded).

Browser maps `KeyboardEvent.code`, pointer events and every connected Gamepad API controller in the standard mapping. Native maps Sokol keyboard/pointer/touch events and up to four Linux evdev controllers (Sokol supplies no gamepad API), with fixes for known drivers (xpad's face buttons, a generic HID pad's right stick on Z/RZ, digital triggers); there is no mapping database, and the checks feed recorded evdev events through a pipe, not a physical controller. Sticks are clamped to [-1,1] and both triggers to 0..1. `Gamepad.getAxis` and `getPadAxis` apply a radial dead zone (`setDeadzone`); action thresholds are game policy (`Controls.hx`). Controller disconnect returns neutral state. Gamepad polling cannot preserve a physical press/release that happens entirely between samples; keyboard/pointer event edges can.

Pointer positions use top-left-origin **framebuffer pixels**, not CSS pixels. Browser converts client coordinates using the canvas rectangle and framebuffer size; native supplies Sokol coordinates. Shared `Menu` maps them through letterboxing to 960×720 design coordinates. Only a primary pointer is exposed; pointer support does not constitute multitouch flight/fire controls.

`InputState` is the shared accumulator the router feeds; autopilot and tests feed it directly. Autopilot supplies normal input to the same game/menu code and observes explicit app probes. Its bounded JSON parsing uses `Reflect` for schema field checks, not shader or game-internal reflection. See [PACKAGING.md](PACKAGING.md).

## Audio

An **asset** is encoded source bytes identified by a path. An **audio resource** is reusable playback data. `AudioClip` holds fully decoded PCM; `AudioStream` holds a progressively decoded source. `AudioPlayback` is one playing or paused instance. Streaming describes delivery/decoding, not where the encoded source lives: a stream can use a stored file or a remote URL. There is no separate audio player object or persistent spatial emitter in this slice.

Use shared `AudioResources.loadClip(path, callback)` or `loadStream(path, callback)`, returning `Ready(resource)`, `Failed(message)` or `Cancelled`. These return an `IRequest`. `play(resource, loop, volume)` returns an independent `AudioPlayback` with `stop()`, `pause()`, `resume()`, `setVolume()`, `getState()` and `isFinished()`. `resource.release()` drops the caller's ownership once; active playbacks retain it until stopped or naturally finished. A released resource cannot start another playback. Pausing retains the resource and any source lease. The `Runner` polls natural completion and shuts down resources before the backend.

`loadClip` requires a successfully ensured encoded asset, then decodes it through the shared `AudioDecoding`: it sniffs the file (RIFF, `OggS`, an ID3 tag or an MPEG frame's sync bits), decodes a WAV itself with the shared `Wav` (mono PCM16 at 44100 Hz, at most four seconds), hands Ogg (Vorbis, Opus) and MP3 to the platform's `IAudioDecoder`, holds encoded files to 8 MiB and decoded clips to 2Mi frames, checks the PCM, and runs at most two decodes at once on a `Jobs` pool, each completing once on the host thread (`Decoded(monoFloat32Bytes)`, `Failed(message)` or `Cancelled`). `loadStream` resolves usable storage first, then a remote URL, and opens it with `IAudio.openStream`. Browser storage supplies a leased Blob URL; remote playback uses an audio element without storing the download. To guarantee storage, call `assets.ensure()` before `loadStream()`. No simultaneous play-and-store path is implemented. Service network counts prove each ensured WAV/Vorbis/Opus fixture downloads once across cache reads, clips, streams and a second process/page.

`IAudio` is the platform's output and nothing more: whether it exists (`isAvailable`) and runs now (`isRunning`), clips copied from mono float32 PCM at 44100 Hz, streams opened from an `AudioLocation` (`openStream(source, done)` answers `Opened(id)` or `Failed(message)` on the host thread and returns an abort), voices started from either (`playClip`, `playStream`), stop/pause/setVolume/isPlaying, destroying clips and streams (each stops its voices on both targets), poll and shutdown. Ids are the adapter's. `AudioPlayback` owns what is the same everywhere: a playback asked for before audio runs waits and starts at a later poll once it does (a browser runs audio from the page's first key or pointer press), volumes are checked before they reach an adapter, and a voice of 0 (no free voice) or no output at all yields an already finished playback. The typed resource layer owns destruction; applications should not mix direct handle destruction with its lifetime methods.

In a browser, `WebAudioDecoderAdapter` decodes Ogg and MP3 with `decodeAudioData` on a 44100 Hz `OfflineAudioContext` (no user gesture needed; it resamples) from an owned copy of the bytes, and mixes the channels down. `WebAudioAdapter` is output only: its `AudioContext` is made on the first key or pointer press (browsers allow audio to start only in a gesture) and suspended while the page is blurred or hidden; clips play through buffer sources and gains, streams through an `HTMLAudioElement`. Ogg/Vorbis and Ogg/Opus clips ran in Chromium in the service checks; MP3 is accepted the same way. This does not establish every browser's codec availability. Decoder rejection reports failure. Browser decoding is asynchronous, but the mixdown and copy run on the host thread and are not preemptible.

Natively, `audiodecoder/libsndfile` is a codec adapter of its own over a thin C **libsndfile 1.2.2** bridge (libsndfile reads MP3 through mpg123 from 1.1 on): `LibsndfileAudioDecoderAdapter` (the `IAudioDecoder`, decoding whole Ogg/Vorbis, Ogg/Opus and MP3 files on worker threads, handed back through the `Mailbox`) and `LibsndfilePcmFiles` (files read a part at a time for streaming, Ogg, MP3 and WAV). Mono/stereo sources with rates 8000–192000 Hz downmix and linearly resample to mono 44100 Hz in C; decoder PCM need not match browser PCM bit for bit. The limits bound returned PCM, not the internal allocations of a browser/library decoder. Logical cancellation delivers one terminal result and suppresses late completion; it cannot interrupt browser decoding or a native codec call already running.

`SokolAudioAdapter(files)` is the native output: a mutex-protected mixer in C with 32 clip slots, 16 voices and device-rate resampling, and streams read through an `IPcmFiles` (the profile gives it `LibsndfilePcmFiles`). A stored stream is opened once on a worker to check it reads; each voice opens the file again and its poll keeps it up to 8192 frames ahead, 2048 frames a read, for up to 2 ms a frame, rewinding on loop. Underruns produce silence and keep the voice; the end finishes it after queued data drains. The pump stays in this adapter: it is how a push-based output plays a file as it's read, and an output fed from its own callback would read there instead. A second push-based output (SDL3's audio streams can be pushed to) would move the pump to shared code. The device mixer runs independently, but a host stall beyond queued audio (~186 ms at 44100 Hz when full) can interrupt a native stream; this differs from native reference decoding on the audio thread and needs a stall workload. A direct stored source is not subject to whole-file fetching's 8 MiB cap. Natively a stream plays any WAV libsndfile reads, while a WAV clip takes only the shared decoder's mono PCM16 at 44100 Hz.

This is streaming decoded chunks from a stored file. Native remote streams explicitly fail with an instruction to ensure first. Browser remote fixture playback/cleanup passed, but the small fixtures do not prove playback starts before network EOF. Native network streaming, play-while-keeping on both targets and proof of slow-network startup are milestone 7 ([ROADMAP.md](ROADMAP.md)). General WAV clip layouts remain a separate gate. MP3 clips and streams are accepted on both targets (the `audio-music` example opens its music as an MP3 stream), but no check covers MP3 yet: the service checks have no MP3 fixture.

The existing shared WAV clip decoder also has a stricter four-second PCM16 data limit; longer canonical WAV can use the stored stream path. Ogg and MP3 clips instead use the 2Mi-frame cap (about 47 seconds). These are current prototype limits, not a general audio library specification.

Asteroids now delivers eight quality 3 Vorbis files made from its original generated WAV sources using offline FFmpeg. It plays fully decoded clips. The revised thrust-v4 asset is a two-second circular noise/motor loop; shared game code applies a tick-based volume attack/release through existing setVolume calls. This is game policy, not a general sample-accurate fade API. Separate fixtures exercise WAV/Vorbis/Opus clips and streams, including stereo 48 kHz Opus input, malformed/empty files and decode cancellation. Real ALSA callbacks and PCM mixer assertions ran; checks do not establish audible output quality. Stereo **output**, pitch/pan/seeking, segments, buses, fades, spatial audio and richer playback-error reporting remain unfinished. SDK pin/license and the external native decoder dependency are recorded in BUILDING.md and dependencies.json; no decoder is shipped in browser Wasm.

## Assets

`AssetService` implements `IAssets` over the shared `Fetch` and `Storage` (themselves over the platform's `IHttp` and `IStore`). `ensure(path, callback, ?progress)` returns `IRequest` and later `Loaded(Bytes)`, `Failed(message)` or `Cancelled`. It checks encoded storage first, fetches or reads packaged bytes on a miss, and reports success only after a committed storage write. Progress contains a phase (locating/downloading/storing/ready), received bytes and nullable total. The compatibility `load()` delegates to ensure. `streamSource()` resolves a leased local source before a remote URL without ensuring or downloading it. Assets are source files; textures/clips/streams are runtime resources; playback/model placement are instances. A future glTF asset can produce mesh and texture resources without reversing that direction.

`IAssets.subscribe(path, target:IReloadable)` asks for `target.reloaded(path, bytes)` when that file changes and has loaded again; `unsubscribe` ends it. `AssetService.changed(path)` does the loading, past the HTTP cache (`FetchRequest.noCache`) and the stored copy, and stores the new copy; only `-D hotreload` browser builds call it, from hotreload-hx's changed-file notices. A failed reload keeps what subscribers have and is traced. `AudioResources` subscribes for its clips and swaps a reloaded clip's backend clip in place.

Paths reject schemes, absolute names, traversal and unsupported characters. Storage keys hash the asset base URL plus path; this separates hosts, but does not provide content versioning, integrity manifests or freshness validation. Browser uses IndexedDB encoded Blobs; native uses files with sibling temporary writes and replacement. Native packaged assets are under the executable's `assets/`; downloads are cached in `HELIX_CACHE` if set, else the user's cache directory for the program's identity (`$XDG_CACHE_HOME` or `~/.cache`, then company/product), else `cache/` beside the executable. This is a prototype cache, not a user-data sandbox or production platform cache-location policy. Storage quotas/errors fail explicitly; ensure does not silently bypass failed persistence.

## Fetch, storage, decoding and cancellation

`Fetch.fetch({url, ?maxBytes, ?timeoutSeconds, ?noCache}, callback, ?progress)` reports `Response({status,headers,bytes})`, `Failed(message)` or `Cancelled`. HTTP error statuses are responses; asset policy rejects non-2xx statuses. Defaults are 8 MiB and 15 seconds, the timeout covering the whole transfer on both targets. Headers are lowercase; the total is unknown for a compressed body. Progress runs at most once a frame. `Storage` reads and writes whole files of at most 8 MiB by key (an asset path); a read-only `Storage` (the packaged assets) refuses writes. `ImageDecoding` decodes images for textures and environments. All three, and `AudioDecoding`, run on `helix.core.Jobs`: at most two operations at once, each completing exactly once on the host thread at a later poll, cancelled ones (and those pending at shutdown) completing `Cancelled`, later ones refused with a failure.

Under them the platform contracts are operations (`IHttp.get`, `IStore`, `IImageDecoder.decode`) answering on the host thread, never during the call. Cancellation calls the platform's abort: a browser aborts its request; natively a transfer stops at its next part of the body (not while it connects), and a storage operation already running finishes on its own, its answer dropped. Cancellation doesn't undo a completed write. Delivery is cooperative (`WorkQueue`, nominally 2 ms a poll for each pool); it can't preempt a callback, decode or platform call. Whole downloads are assembled in memory; downloading straight into storage and resuming need a separate gate. Native HTTPS compiles but isn't yet an executed interoperability claim.

## Deferred scope

SDL3 is a candidate for a complete native platform adapter: graphics, window/input, gamepads and audio. Services can be selected independently, including mixed Sokol/SDL3 configurations; a second backend must preserve resource/lifetime/input/shader contracts and run the same tests. No SDL3 backend or matched SDL3 performance result exists yet. Desktop performance takes priority over executable size. A comparison must include shader generation and executed modern graphics, not infer behavior from available APIs.

Context/device recovery, modern native graphics APIs (Vulkan, Metal, D3D) and WebGPU remain graphics gates. Asset manifests/versioning/revalidation, eviction/quotas, concurrent ensure deduplication, large downloads, normalized HTTPS/redirect/deadline behavior, remote native streaming, further codecs/playback controls, user-data storage, multitouch and text input remain service gates. Add operations for exercised needs; this remains a thin interface over actual adapters.

## Composition

Contract packages live under `helix.audio`, `helix.graphics`, `helix.input`, `helix.assets`, `helix.host` and `helix.debug`; `helix.core.Jobs` is the shared pool for asynchronous platform work and `helix.core.WorkQueue` supplies cooperative callbacks. Adapters live under `helix.adapters.<contract>.<api>`, named `<Api><Contract>Adapter` ([ARCHITECTURE.md](ARCHITECTURE.md)); their C sources, headers and extern bindings under the adapter's `internal/` directory, built by `adapters/internal/SokolNativeBuild.hx`. A profile in `helix.profiles` picks a host and an adapter for each contract and runs an app on them through the `Runner`: `BrowserWebGL2Profile.run` (WebGL2, DOM, Web Audio, Fetch API, IndexedDB, the page's image decoder) and `NativeSokolGLProfile.run` (sokol on GL 4.1, sokol audio with libsndfile, evdev gamepads, haxe.Http, files, stb_image). The rule for what may live in an adapter, and its check, are in [ARCHITECTURE.md](ARCHITECTURE.md).
