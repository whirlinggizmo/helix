# History

What was built, milestone by milestone, and what each step found. Every entry links to the decisions behind it, in [DECISIONS.md](DECISIONS.md) (numbered, in order: the record the code and docs cite). What's next: [ROADMAP.md](ROADMAP.md). Text here is kept as written, so a name in it may since have changed.

## Before HeliX: the architecture study

HeliX began as experiment 05 of whirlinggizmo's framework architecture study, a Haxe framework compared against libwgf (C): one Haxe program built to JS for the browser and to C++ through hxcpp natively, over thin platform adapters. Asteroids was its first slice. Two probes decided whether it went on: hot reload in the browser through hotreload-hx (probe 1, during milestone 1), and the cost of 3D on the CPU (probe 2, 2026-10-13, before milestone 2: Haxe matched libwgf's C natively and its Wasm in V8).

## Milestone 1: the platform, 2D and services (to 2026-10-12)

The hosts, input (keys, pointer, touch, four gamepads), Web Audio and sokol audio, fetch, storage and the asset cache, 2D batches and text, a fixed-rate ticker, Asteroids and Blocks as examples like the rest, with autopilot scripts that must end in the same game on both targets. HeliX then moved to its own repository; the study keeps its record. Decisions 1–58 (those before the move were made in the study, and name it).

## Milestone 2: 3D basics (2026-10-13)

A frame the app owns and framework shaders by kind; deterministic trigonometry for simulations (`helix.math.Trig`, the same bits in the interpreter, JS and hxcpp); retained stages of render nodes beside the immediate batches; lit models through an instance buffer and a trimmed PBR shader; normal maps; glTF models read in Haxe. Decisions 59–64.

## Milestone 3: 2D stages and the rest of 2D (2026-10-13)

`Stage2D`; sampling per draw and compressed textures picked by GPU; TrueType read and baked in Haxe; render targets; apps' own shaders as assets, surface shaders on Stage3D materials, screen effects. Decisions 65–70.

## Milestone 4: advanced 3D (2026-10-13 to 2026-10-14)

Camera nodes; glTF from .gltf files and files beside them; mirrored models; textures shared by file; 3D sprites and text; GPU particles in 2D and 3D; shadow maps (the sun's texels held still in the world); environments (split-sum image-based light, prepared a step at a time). Decisions 71–79. Then skinning and skeletal animation: skins and clips bound by joint name, a file of animations playing on any skeleton with its names, gear swapped at run time, sockets, crossfades, one joint texture a pass, culling by the posed joints. Decision 87.

Checked at its end (2026-10-14): the full tests with native (unit, shader tools, package smoke, the C services test, the trig bits), the services on both targets, Asteroids' and Blocks' autopilots ending in the same game on both, and every 3D example natively on the private display (the animation example driven by keys: clips, the sword socket mid-crossfade, the outfit swapped, posed shadows). On that software-rendered display the environment took 11.8 s to prepare: its bake is tied to a per-frame budget ([ROADMAP.md](ROADMAP.md)).

### The adapter audit (2026-10-14)

Midway through milestone 4, the platform adapters were found repeating engine policy, each its own way. They became a hardware abstraction layer with a rule (an adapter holds only what differs because of its platform) and a check that enforces it: graphics as data, the host split from the engine's runner, one job pool under fetch, storage and decoding, audio output apart from audio decoding, input adapters as event sources feeding one router, adapter directories and classes named by rule, and screenshots (the frame read back, PNG encoded in Haxe, saved through `IExport`). Decisions 80–86; the audit's findings and plan: [ADAPTER_AUDIT.md](ADAPTER_AUDIT.md).

## Milestone 5: scene and pick (2026-10-14)

libwgf's three node flags (enabled, visible, pickable) on 3D and 2D nodes (decision 88). The ray through a pixel of a camera's viewport; picking a Stage3D by each model's triangles (skinned ones as posed), sprites and text by their quads; picking a Stage2D by each kind's own area; `helix.scene.Pointer` over stages, topmost first, a press on 2D capturing it (decision 90). Lights chosen per model: a table of 16, each model's 8, in its record (decision 89, fixing the first-four-lights finding). A culling switch, libwgf's shadow-caster case checked, and `tools/bench_stage.py`: culling worth almost everything out of view, a pick through 4000 models under a sixth of drawing them, and the first light choice found seven times too slow and fixed (decision 90). The `scene3d` and `pick` examples. Checked at its end: the full tests with native, the services on both targets, the autopilots, `scene3d`, `pick`, `lights`, `shaders`, `shadows` and `animation` natively (a sphere hovered and clicked through the pointer on the private display).

## Milestone 6: UI (2026-10-14)

`helix.ui`: wgrender-c's widgets of nodes, asked each frame, with libwgf's focus by keys and pads and its friction fixed (a key held into a new screen ignored, the ring only when keys moved focus, the keys reported so a game leaves them be); a layout of rows, columns and anchors in Haxe (Clay's passes, no Clay); label, panel, button, toggle, slider, progress bar, list and text field; beneath them a scissor in IGraphics, nested clips, nine-slice sprites and wrapped text (decision 91). Replay made independent of timing: scripts wait on state with limits in seconds for what isn't the simulation's, games start each replayed phase fresh (Asteroids' title rocks became dressing), and scripts use UI by name with the autopilot's `click`, as web suites do (decision 92). The `ui` example; Asteroids' menus on helix.ui. Checked at its end: the full tests with native, the services on both targets, both games' autopilots the same final game on both targets, `ui`, `sprite2d`, `stage2d`, `tilemap` and `scene3d` natively (the level list opened by keys and scrolled by the wheel, its rows clipped by the native scissor).

## Milestone 7: Windows, macOS and CI (2026-10-15)

HeliX beyond Linux. Windows builds with MSVC and hxcpp alone, with XInput gamepads, a portable lock and libsndfile's pinned release; MinGW was tried and dropped (decision 99). `tools/remote_windows.py` builds and tests the working tree on a Windows machine over ssh, and with `--desktop` runs in the session logged in at its screen, so windows open on its GPU. macOS compiles the host as Objective-C and builds for the machine's architecture (decision 100). sokol-shdc is fetched and hash-checked per system (`tools/shdc.py`), and the tools read and write UTF-8. A CI workflow runs the tests, `Trig`'s bits and a native build on Linux, Windows and macOS on every push, and daily the services and autopilots on Linux and every example's native build on Windows and macOS (decision 101). Its first runs found CRLF checkouts breaking the pinned headers' hashes, Homebrew's `ffmpeg` without Vorbis, and NaN bits differing between x86 and arm64 in `Trig`'s probe. Checked at its end: the tests on all three systems, with `Trig`'s hash the same on every target of each (`597f07dd…`); all 35 examples' native builds on sightblinder and on CI's Windows and macOS; both games' autopilots the same final game natively in a window on sightblinder (an RTX 2060) as in its Edge; and on Linux the full tests with native, the services on both targets, both autopilots, the type check, and `asteroids`, `hello3d`, `ui` and `shadows` natively. Not checked: sound heard through WASAPI or Core Audio, and any window on a Mac.

## Milestone 8: SDL3, a second native profile (2026-10-15 to 2026-10-18)

SDL3 beside sokol under the same contracts, pinned at 3.4.18 and fetched or built by `tools/sdl3.py` (decision 103): an SDL host, window, input (SDL's gamepad database, rumble) and audio stream (105), native builds per adapter with what they share in `adapters/shared` (104), the sokol_gfx adapter drawing in SDL's GL context, then `Sdl3GpuGraphicsAdapter` on SDL_GPU with its Vulkan, Direct3D 12 and Metal backends, its shaders translated as they're packed (107), checked on a real GPU on Linux and on Metal in CI's Mac daily; files replaced in one step on Windows (106); the two native profiles cost about the same, and the SDL host's GL waits on Windows' compositor (108). Around it, what a public set of examples needed: a target's examples share one assets folder, each example's own claimed (109); the examples' site on GitHub Pages, built on every push as a grid of thumbnails with each example's sizes (110); the asset cache revalidating by ETag, following manifests, with Trust and Off modes and native manifests (111), a copy brought from elsewhere remembering where (115); the dressing room, a character creator over part files bound to a skeleton by joint name, picture tiles and focus that moves on screen (112), then outfits moved to the game and the framework keeping the queries, `Models` sharing a file's load (116); a presentation, the app's design fitted to the window once, with the examples laid out for phones upright and on their side, a 3D view keeping its width, and the site's thumbnails captured once their examples have loaded (113); `Services` made static, as every engine's are (114); the test fixtures and Asteroids' sounds committed, so no build needs FFmpeg (117); the tools named verb_noun. Checked at the user's desk on coinspinner (an RTX 4080 laptop, 2026-10-17): the Xbox 360 pad's buttons, sticks and triggers read under both native profiles, and music, a click and a pause heard through both outputs; a 300 ms stall was heard as a gap in a native stream, so a stream keeps 2 s decoded ahead instead of 186 ms (decision 127). The same day on sightblinder's desktop, the Xbox 360 pad read through SDL and through XInput; Windows' touch keyboard came up over the window, as SDL's text input was on from the first frame, so typed text is now asked for only while something takes it, the UI's text field or a game's own `setTextEntry` (decision 128), and checked gone. Direct3D 12's frame cost measured again on the RTX 2060 with `tools/measure_cpu.py` (shadows: sokol GL 8%, SDL3 GL 12%, Vulkan 12%, Direct3D 12 17% of a core; nothing drawn: Vulkan 12%, Direct3D 12 7%), its extra in the drawing, not the frame, and closed with the numbers (decision 129). The checkpoint (2026-10-18, after the API rework): the type check; all 38 examples built natively under both profiles on Linux and on sightblinder, and under each in CI's daily groups on Windows and macOS; Asteroids and Blocks the same final game as the browser natively under sokol, SDL3 and SDL_GPU on Linux, and under sokol and SDL3 on sightblinder's desktop (Blocks under SDL3 differed once there and matched on its rerun; the first run's result wasn't kept, so the remote tool now prints a differing result); CI's daily autopilot jobs on Linux and on Metal failed on Asteroids with identical games, the browser having logged a 404 for a `config.json` it hasn't (decision 131 moved the file beside the program); on the rerun Metal was green and the Linux job got past its autopilots to the browser asset cache check, whose native offline visit had never used the cache: the check's offline was a port nothing answers on, and the cache keys by host, so every copy was missing; before the rework the example traced the bare `EOF`, which the check's filter didn't match, so the visit passed vacuously. The check now closes the host on its own port for that visit and reads `EOF` as a failure, and all ten visits pass on both targets locally. Milestone 8 closed.

## Milestone 9: the small utilities (2026-10-17)

What every jam stops to write, pure Haxe with unit suites, the audit's first item ([JAM_AUDIT.md](JAM_AUDIT.md)): `helix.math.Random`, one seeded xorshift32 for the framework, an instance per stream, the same bits on every target, which the particle emitter and both games draw from in place of their own copies (decision 118); a game's clock, `helix.time.Clock` as `Services.clock`, the frames' time scaled and paused as a whole, with `Ticker` moved beside it and fed by it, `Timers` (after, every) and `helix.tween.Tweens` with Penner's easings on its delta (119); `Interpolate` (lerp, remap, clamp, smoothStep, angles the short way round, moveToward, damp) and `Curve`, a path through points, by Bézier control points or straight, open or closed, in 2D or 3D, with a steady speed by distance (120); `helix.collision`, overlaps of rectangles, circles and convex polygons, points, segments, rays and sweeps with where and the normal, a box moved and slid over solid tiles, and a spatial hash (121). The `motion` example shows them together: tweens by every easing, a timer dropping sparks that fall and fade, a ball along a closed curve, a floor by `Collide2D`, colors dealt by the seed, the clock paused and slowed. Haxe's own library gives none of this (a wall-clock `haxe.Timer`, an unseeded `Math.random`), and the earlier frameworks had the random (libwgf's PCG32, one for the program) and collider triggers over an ECS, nothing of the rest.

## Milestone 10: scenes and flow (2026-10-17)

A game's flow on a stack: `helix.scene.Scenes` (push pauses the scene under, pop resumes it, replace swaps the top), a `Transition` drawn over the frames and swapping at its middle, a `Loader` gathering a scene's loads with one progress and the built-in `Loading` shown until they're done (replaceable, or none), the built-in `Splash` pushed by the game and holding until a press, focus lost pausing the game's clock and the top scene (decision 124). With it, `IInput.isActivated`, the browser's user activation applied on every target (122), the callback rule rewritten for lifetime (123), and the runner building the app once the services are filled, as claimed. The `scenes` example runs splash, title, loading, play, pause and back under an autopilot on both targets.

## Milestone 11: the scene file and behaviors (2026-10-18)

A `.scene` file of HeliX's own ([SCENE_FILE.md](SCENE_FILE.md), decision 132): JSON, one tree of entries by kind with a stage section, models by file, prefabs by scene, overrides by path, per-node props and behaviors under their node; `SceneFile` parses, writes canonically (the same bytes on every target, nothing at its default) and captures a live instance back; `SceneFiles` caches, `instantiate` makes the tree onto a stage and a pass through the caches that own models, textures, fonts and environments; `SceneSchema`'s tables with `SceneKinds` as their live side; `tools/gltf2scene.py` from a Blender export's custom properties. Behaviors in a package of their own (`helix.behavior`: `Behavior`, the `Behaviors` pass each `Scene` owns and `Scenes` ticks, `BehaviorRegistry` filled by an `@:autoBuild` macro from `@:prop` fields), which settles the game model: no ECS. With it, `Camera3D`'s projection as a property and its numbers as clamping properties, the glTF reader taking cameras, and `Fonts` a bound service (133). The `scene-file` example is a racer slice entirely in behaviors from one file: Kenney's Racing Kit pieces on a hand-laid loop, the sports car as a prefab with its wheels turned and spun, eight checkpoints, a race director and a chase camera, its autopilot driving a lap to the same final game in Chrome and natively under both profiles. Built as supervised agents per phase from a written plan, the designer reviewing each. Checkpoint (2026-10-18): the type check (177 targets), 27 unit suites and the tool tests; every example built natively under sokol, SDL3 and SDL_GPU on Linux and in CI's groups on Windows and macOS; the scene-file lap and smoke scripts the same final game as the browser natively under sokol and SDL3 on Linux and on sightblinder's desktop, the scenes, Asteroids and Blocks autopilots likewise on Linux and Asteroids on sightblinder; CI's Linux services and autopilots and Metal jobs green. One limit found for later: a prefab can't reference a node outside itself (the car's behavior with its `@race` sits in the track file on the prefab's node).

## The API in Haxe's own terms (2026-10-17)

The three rules inherited from the C frameworks (a method for every value, a node as one struct with a type field, services through a holder) dropped for Haxe's own forms, as CONVENTIONS' Names section now says (decision 130), in six phases and one sweep, every caller changed with each and nothing kept for compatibility (259 files across the rework). Kinds as classes in 3D: `helix.scene.Node` under `Node3D`, and `Model` (its parts), `DirectionalLight`, `PointLight` and `SpotLight` on `Light`, `Camera3D` a node viewing from its world transform, `Sprite3D`, `Text3D`, `Particles3D`; `NodeKind`, `getKind`, `LightKind` and every `Node.xxx` constructor gone, glTF nodes instantiated as one `Model` each, the stage keeping typed lists (56 files, 18 examples). Services as static classes: `Services` gone for `Host`, `Window`, `Screen`, `Input`, `Graphics`, `Audio`, `Assets`, `Fetch`, `Storage`, `Textures`, `Models`, `Environments`, `Screenshots`, `TestHarness` and `Time`, their forwarders written by a build macro (`helix.macro.Facade`) from the interface or class, the classes they stand over renamed `...Cache` and `...Service` (714 lines of callers in 116 files). Properties: 760 accessor methods became about 600 properties, refusing setters clamping and saying their range, several values at once and "can't now" staying methods (214 files). Kinds as classes in 2D: `Node2D` on `Node`, with `Sprite2D`, `Shape2D`, `Text2D` and `Particles2D`, immediate text moved to `Batch2D.drawText` and `Font2D` (138 text calls in 43 files, 89 node constructions). Completions take lambdas: `load(path, loaded, ?failed)` for models, textures, environments, clips, streams, fonts, shaders and assets, eight result enums and 73 `Cancelled` arms gone, 53 switches in 29 example files become lambdas calling a method by name, an unhandled failure logged with its path once (`helix.assets.Failure`). Last, the model example rewritten as the showcase (the car loaded in one line, its tree said in a comment, wheels and headlights found by name, a ride-along `Camera3D` under the car), the examples' circling camera shared as `Orbit` by thirteen examples, and the 34 callbacks hotreload-hx warned about made lambdas calling by name; functions used as data (easings) stay. Checked at each phase: the formatter, the type check on both targets, `0 undocumented`, the generated reference, the unit tests natively, all 38 examples built for web, and the asteroids, blocks and scenes autopilots the same in the browser and natively; at the end every example built natively under SDL3 (animation and the dressing room only once `Node3D.collectModels` stopped calling through the typed `getChild`, whose override hxcpp declares with `Node`'s return, broken natively since the kinds became classes), all 38 run in headless Chromium beside the site's thumbnails, and the model example's hot reload swapping an edit in. That last needs a fix in hotreload-hx, not yet made there: since the properties phase its browser build gives a computed static property (`Time.time`, `Host.busy`) a first value it can't hold, so every HeliX hot build fails to compile; checked with the fix in a local copy.
